# 📡 Sonar Radar Pro V6.6.0 RC3

**Version:** `6.6.0-rc3` · **Telegram + VPS Agents + Web Panel** · **Status: Release Candidate (not production-certified)**

مدیریت VPS، نصب ایجنت رمزنگاری‌شده، تست کانفیگ‌های Xray، مدیریت سابسکریپشن، مانیتورینگ چندنقطه‌ای، هشدارها، بکاپ و عیب‌یابی از طریق تلگرام و پنل وب.

> ⚠️ این کد هنوز روی یک VPS واقعی با Telegram، PostgreSQL و SSH/WSS انتهابه‌انتها آزمایش نشده است. «آمادهٔ نصب آزمایشی» به معنی «آمادهٔ استفاده در محیط تولید» نیست. ابتدا روی **سرور آزمایشی** نصب کنید و نتیجه `--doctor` و `--support` را بررسی کنید.

## ◉ تغییرات نسخه ۶.۶ آزمایشی

تغییرات کد، حدود تست و نکات ضروری نصب در `RELEASE_6_6_RC3_FA.md` و `DEPLOY_6_6_RC3_FA.md` آمده‌اند. سندهای RC1 برای سابقهٔ نسخهٔ قبلی در بسته باقی مانده‌اند.

## ◉ مسیر نصب مقاوم در برابر اختلال در 6.5.0

مسیر مستقیم و fallback آفلاین Python wheel و آرشیو پین‌شده Xray، گزارش پیشرفت نصب، راهنمای وب/تلگرام و اصلاح گزارش‌ دوره‌ای اضافه شده است. جزئیات و محدودیت‌ها در `RELEASE_6_5_FA.md` آمده است. همچنان این بسته نسخه RC است.

## ◉ بازطراحی منوها و اشتراک منابع در 6.4.0

پنل ربات در شش بخش اصلی مرتب شده است. ثبت هم‌گروهی با تأیید گیرنده، فضای مشترک سرورها، کانفیگ‌ها و تنظیمات فنی و اعلان فعالیت‌های تیمی به این نسخه اضافه شده است. تغییر IP سرور از تنظیمات همان سرور انجام می‌شود. فایل‌های Agent/WebSocket تغییر نکرده‌اند. اطلاعات مالی و حساب شخصی مشترک نمی‌شوند.

## ◉ اصلاح ناوبری در 6.3.1

دکمه‌های بازگشت در منوهای اصلی، صفحه‌بندی فهرست کانفیگ‌ها، لغو عملیات و ثبت موفق اکنون به صفحه‌ی مرتبط برمی‌گردند، نه دسته‌بندی سراسری. برای شرح مسیرها و نصب فایل ZIP **همین نسخه**، `docs/history/RELEASE_6_3_1_FA.md` را بخوانید. فایل‌های Agent و WebSocket دست‌نخورده‌اند.

## ◉ قابلیت مانیتورینگ جدید در 6.3

مانیتورهای HTTP(S) و TCP را در بخش **مانیتورینگ** پنل وب ایجاد کنید یا از `/uptime` در ربات استفاده کنید.
هشدارها پس از تعداد خطاهای متوالی تنظیم‌شده فعال می‌شوند؛ برطرف‌شدن خطا رخداد را می‌بندد.
حریم امنیتی این قابلیت، جلوگیری از دسترسی به شبکه داخلی از طریق URLهای کاربران است.
برای جزئیات نصب آزمایشی و محدودیت‌ها، فایل `RELEASE_6_3_FA.md` را بخوانید.

## 🚀 نصب آسان از GitHub

مخزن پروژه: **https://github.com/Amirtn9/radarsonarplus**

پیش‌نیاز: Ubuntu 22.04/24.04 یا Debian دارای systemd، دسترسی sudo، اینترنت، توکن ربات از **@BotFather** و شناسه عددی ادمین. پنل عمومی به دامنه و HTTPS نیاز دارد. برای ایجنت جداگانه یک VPS و دسترسی SSH لازم است.

```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates

git clone https://github.com/Amirtn9/radarsonarplus.git
cd radarsonarplus
bash install.sh --check
sudo bash install.sh
```

در منوی نصب، **01** را بزنید و مراحل راهنما را دنبال کنید. نصاب در صورت نیاز دسترسی مدیر را با `sudo` درخواست می‌کند؛ برای بازکردن مجدد منو همان `./install.sh` را اجرا کنید.

**مهم:** ابتدا باید فایل‌های این نسخه واقعاً به مخزن GitHub پوش شوند؛ `git clone` نسخه فعلی مخزن را می‌گیرد، نه محتوای ZIP این گفتگو. برای انتشار قابل‌راستی‌آزمایی، SHA کامل commit بازبینی‌شده را ثبت کنید. در حالت bootstrap نصب‌کننده از `main` استفاده می‌کند؛ بدون SHA تأییدشده، زنجیره تأمین کاملاً پین نشده است.

### نصب پاک یا بروزرسانی؟

**ارتقا و نصب معمولی نباید بی‌صدا اطلاعات را پاک کنند.** نصب پاک برای شروع از صفر وجود دارد اما ابتدا داده‌های اختصاصی برنامه، فایل پیکربندی، کلید رمزنگاری و دیتابیس آرشیو می‌شوند و سپس با عبارت تأیید دقیق حذف انجام می‌شود. دیتابیس‌های دیگر، SSH سیستم و سرویس‌های نامرتبط نباید حذف شوند.

برای اجرای مستقیم:

```bash
sudo bash install.sh --install
sudo bash install.sh --update
sudo bash install.sh --clean-install
```

از اجرای `--clean-install` روی سیستم دارای اطلاعات مهم بدون اطمینان از بکاپ خودداری کنید.

ارتباط ایجنت با **WSS دارای TLS و توکن اختصاصی** است. SSH نیز نیازمند تأیید اثرانگشت میزبان است. اگر افزودن سرور با خطای `HOST_KEY_UNKNOWN` مواجه شد، اثرانگشت اعلام‌شده را **از کنسول مستقل سرور** کنترل و با گزینه اعتمادسازی در نصاب ثبت کنید. برای دورزدن خطا، `RejectPolicy` یا بررسی TLS را غیرفعال نکنید.

## 🔗 سابسکریپشن و تست کانفیگ‌ها

- دریافت اشتراک از HTTPS با پورت‌های مجاز `443`, `8443`, `2096`, `2053`, `2083`, `2087`.
- کنترل مقصد عمومی DNS، جلوگیری از SSRF، رد Redirect، محدودیت حجم ۲ MiB و سقف ۶۰۰ آیتم.
- پردازش لینک‌های متداول VMess، VLESS، Trojan، Shadowsocks، Base64، بخشی از Clash YAML و Sing-box JSON.
- حفظ TLS/SNI، WS/gRPC، Reality `publicKey`/`shortId`، ALPN و fingerprint در ترکیب‌های پشتیبانی‌شده.
- ویژگی‌های ناشناخته/ناسازگار **نباید بی‌صدا با حالت ساده‌سازی‌شده تست شوند**؛ برای برخی فرمت‌های پیچیده، آیتم پشتیبانی نمی‌شود.
- در همگام‌سازی، شکست تست **به معنای حذف آیتم از منبع نیست**. وضعیت `Unknown` برای نتیجه نامشخص استفاده می‌شود.
- حذف آیتم‌های غایب از منبع فقط در شرایط محافظه‌کارانهٔ تأیید کامل‌بودن لیست انجام می‌شود. سابسکریپشن ساختاریافته یا پاسخ محدودشده به سقف، بدون حذف خودکار نگهداری می‌شود.
- سنجش دانلود اختیاری موجود است؛ **تست آپلود واقعی** هنوز پیاده‌سازی نشده است.

## 🩺 وقتی ربات کار نمی‌کند

از داخل تلگرام به‌عنوان ادمین:

```text
/doctor
```

خروجی ZIP شامل بخش‌هایی از اطلاعات سلامت، وضعیت ایجنت، سرویس‌ها، لاگ برنامه/وب/نصاب و خطاهاست. دریافت لاگ از پنج ایجنت می‌تواند طولانی شود و در پس‌زمینه اجرا می‌شود تا همه کاربران منتظر آن نمانند.

**حتی اگر ربات اجرا نشود:**

```bash
sudo bash install.sh --doctor
sudo bash install.sh --support
sudo bash install.sh --logs errors --lines 200
sudo bash install.sh --status
```

فایل ZIP در `/var/backups/sonar-radar/` قرار می‌گیرد. **قبل از ارسال فایل به دیگران، محتوای آن را بازبینی کنید**. سیستم اطلاعات متداول محرمانه را حذف می‌کند، اما هیچ روش پاک‌سازی خودکاری بی‌نقص نیست؛ از انتشار فایل‌های `.env`، کلید خصوصی، توکن خام یا بکاپ دیتابیس خودداری کنید.

## 🌐 پنل وب

پنل مبتنی بر FastAPI / JavaScript و رابط RTL است و فقط از مسیر HTTPS همراه با اطلاعات امضاشده Telegram Mini App استفاده می‌کند. پنجره اعتبارسنجی `initData` حداکثر ۱۰ دقیقه است (پیش‌فرض ۵ دقیقه). `GET /healthz` زنده بودن وب و `GET /readyz` سلامت اتصال واقعی دیتابیس را از هم جدا می‌کنند. نمایش تمام عملیات پرخطر SSH در پنل وب هنوز کامل نیست.


### اصلاحات وب و Agent (پچ روی RC3)

در این بسته، پنل وب و Telegram Mini App مسیر جدید افزودن سرور دارند: ابتدا اسکن SSH مستقیم از سرور مرکزی، سپس در صورت خطای شبکه استفاده از Agent ایرانِ فعال و تأییدشده، نمایش اثرانگشت SHA256 و **تطبیق با اثرانگشت مستقل از کنسول سرور**. سپس احراز هویت، ثبت در دیتابیس اصلی و در صورت تأیید، صف نصب Agent انجام می‌شود. کنترل مالکیت، مدیریت پوشه‌ها و پورت Agent، تست SSH، نصب/تعمیر و نمایش وضعیت نصب از وب اضافه شده است.

**مهم:** این پچ انتقال کامل صددرصدی تمام فرمان‌ها و ویزاردهای ربات نیست. محدودیت‌ها و آزمون‌های عملیاتی را در `docs/WEB_AGENT_FIXES_FA.md` و `docs/QA_WEB_AGENT_FA.md` بخوانید. برای پورت SSH غیرمعمول در fallback، allowlist مرکز و تمام Agentها با `SONAR_AGENT_RELAY_PORTS` تنظیم شود. قبل از ارتقای محیط واقعی از کلید رمزنگاری، دیتابیس و known_hosts نسخه پشتیبان بگیرید.

## ✅ بررسی سورس و تست‌ها

```bash
python3 -m compileall -q .
bash -n install.sh
node --check pro_web/static/app.js
python3 scripts/verify_manifest.py
python3 -m pytest -q tests
```

وابستگی‌های اجرای برنامه در `requirements.txt` و `requirements-web.txt` و وابستگی‌های توسعه و تست در `requirements-dev.txt` ثبت شده‌اند. برای اجرای کامل آزمون‌ها:

```bash
python3 -m pip install -r requirements.txt -r requirements-web.txt -r requirements-dev.txt
python3 -m pytest -q
```

اجرای مجموعه کامل روی محیط فاقد این وابستگی‌ها ناقص می‌شود؛ نتیجه را **NOT_TESTED / BLOCKED** تلقی کنید، نه موفقیت. وضعیت دقیق آزمون‌ها در [`QA_V6_RC1_FA.md`](docs/history/QA_V6_RC1_FA.md) آمده است.
