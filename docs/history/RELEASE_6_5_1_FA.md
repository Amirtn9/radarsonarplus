# SONAR RADAR PRO v6.5.1 — Web Console / Compatibility Patch

## وضعیت انتشار

این نسخه **Release Candidate قابل آزمایش** است. ارتباط واقعی Telegram/WSS/SSH، نصب روی VPS و صحت داده‌های PostgreSQL روی سرور مقصد در این محیط قابل آزمایش نبوده است. ابتدا روی VPS آزمایشی نصب شود. این نسخه جایگزین منطق اصلی ربات یا Agent نیست.

## منبع و مرز تغییرات

مبنای کد: ZIP `Sonar_Radar_Pro_v6.5.0_Agent_Offline_UI_RC.zip` ارسالی در گفتگو.
هفت مخزن مرجع بررسی شدند، ولی **هیچ پروتکل، جدول DB یا Agent از آن‌ها مستقیماً جایگزین نشد**. هدف استخراج الگو بود، نه مخلوط‌کردن کدهای ناسازگار یا نقض مجوزها:

| مرجع | الگوی مورد استفاده در طراحی | چیزی که عامدانه جایگزین نشد |
|---|---|---|
| ServerBee | کارت منابع، تاریخچه و نمایش وضعیت Agent | Rust WebSocket/Agent و ثبت‌نام مخصوص ServerBee |
| telnoc | داشبورد NOC و تفکیک سطوح خواندن/فرمان | SocketIO، Redis، دستورات امضاشده خارجی |
| ServerOpsMonitor | تفکیک داشبورد وب و عملیات تلگرام | Ansible و مدل AsyncPG جدید |
| systatbot | وضوح مسیر عضویت و مدیریت دسترسی | JWT و دیتابیس SQLite مجزا |
| Uptime Kuma | تاریخچه وضعیت سرویس و کنترل رخداد | Socket.IO و مدل مانیتورینگ/منطق زمان‌بندی جایگزین |
| netmon-telegram-bot | نمایش خلاصه وضعیت و اعلان رخداد | مدل قدیمی Python و ping خارجی |
| server-control-suite | الگوی داشبورد منابع و اقدامات محافظت‌شده | ترمینال راه‌دور، فایل‌منیجر یا دسترسی روت از وب |

## چه چیز اضافه شد؟

1. `console_api.py`: APIهای مکملِ محدود به فضای کاری جاری: جزئیات ایمن سرور، جزئیات کانفیگ بدون لینک خام، فهرست کانال‌های اعلان با شناسه ماسک‌شده و رویدادهای اخیر. فیلدهای خروجی روی allowlist ثابت محدودند؛ احراز هویت از **همان Telegram initData** و کنترل دسترسی `ProStore.workspace` نسخه قبلی استفاده می‌کند.
2. `POST /api/console/tags` و `POST /api/console/rules`: اتصال کنترل‌های وب به متدهای **موجود** `ProStore.add_tag` و `ProStore.set_rule`، بدون بازنویسی موتور هشدار/قوانین.
3. `pro_web/static/console.js`, `console.css`: صفحات جزئیات سرور و کانفیگ، نمودار تاریخچه ۲۴ساعته، فهرست کانال‌ها، تایم‌لاین فعالیت‌ها، بازخوانی خودکار ۴۵ ثانیه‌ای در صفحات قابل مشاهده. این ویژگی، **WebSocket زنده نیست**؛ بازخوانی از داده‌های ذخیره‌شده است.
4. `pro_web/index.html`, `pro_web/static/app.js`: دسته‌بندی ساده‌تر پنل، دکمه ورود به جزئیات، جستجوی علاقه‌مندی‌ها و برچسب‌ها، فرم مدیریت قانون اعلان. فرم اضافه‌کردن عضو در وب که با ویزارد تأیید دوطرفه ناسازگار بود، مخفی شده و راهنمای انجام عملیات از تلگرام جایگزین شده است.
5. `pro_portal.py`: تنها اتصال ماژول مکمل به FastAPI موجود و اصلاح عنوان نسخه.
6. `VERSION`, `settings.py`, `install.sh`: فقط شناسه نسخه به 6.5.1 بروزرسانی شد؛ منطق اجرا/نصب install.sh تغییر نکرد.
7. تست‌های API جدید و بروزکردن **انتظار نسخه** در دو تست قدیمی.

## موارد محافظت‌شده و بدون تغییر

مقایسه SHA-256 فایل‌های مبنا و نسخه جدید نشان می‌دهد فایل‌های زیر عیناً یکسان‌اند:

`ws_client.py`, `monitor_agent.py`, `agent_deploy.py`, `agent_bootstrap.py`, `agent_xray_bridge.py`, `database.py`, `scoring.py`, `pro_scoring.py`, `cronjobs.py`, `cronjob_hub.py`, `tunnel_logic.py`, `bot_logic_mod/tunnels.py`, `bot.py`, `dispatcher.py`, `workspace_service.py`.

**هیچ تغییر جدیدی در** Agent، WebSocket، TLS enrollment، تنظیمات SSH، routing، balancer، جدول دیتابیس، قراردادهای تلگرام یا روش‌های انتقال نصب 6.5.0 ایجاد نشده است.

## آزمون‌ها

- ۸ تست اختصاصی API و امنیت وب نسخه ۶.۵.۱: **موفق**، از جمله دسترسی بدون احراز هویت، محدودسازی owner، ماسک کانال، اعتبارسنجی مدل ورودی و عدم نمایش رمز/token/link.
- مجموعه منتخب شامل نصب آفلاین، ناوبری، مانیتورینگ و API جدید: **۳۶ تست + ۸ زیرآزمون موفق**.
- کل مجموعه `pytest -q`: **۱۴۲ موفق، ۴ شکست، ۲ خطای آماده‌سازی، ۸ زیرآزمون موفق**. چهار شکست و دو خطا به نبود `paramiko` یا `telegram` در **محیط آزمایش** مربوط است؛ این تست‌ها بعد از نصب وابستگی‌های موردنیاز باید روی VPS staging تکرار شوند.
- Python compileall، `node --check` برای دو فایل JS، `bash -n` برای نصب‌کننده و اسکریپت‌ها: **موفق**.
- ارجاع‌های ID جاوااسکریپت و تکراری‌نبودن idهای HTML: **موفق**.
- بازتولید `MANIFEST_SHA256.txt` و `verify_manifest.py`: **موفق**.

## محدودیت‌ها

- صفحه وب برای **مشاهده و مدیریت سرویس مانیتورینگ، علاقه‌مندی، برچسب‌ها، قوانین هشدار و ترجیحات** قابل استفاده است. افزودن/حذف/تغییر IP سرورها، مدیریت tunnel/routing/balancer و نصب Agent **همچنان از ویزارد ربات تلگرام** انجام می‌شوند؛ عمداً API موازی اجرایی برای این عملیات ایجاد نشده است.
- اعتبار نشست Mini App در نسخه مبنا کوتاه‌مدت است؛ پس از انقضا، کاربر باید پنل را از ربات دوباره باز کند.
- تازه‌سازی ۴۵ثانیه‌ای فقط داده‌های ثبت‌شده را نشان می‌دهد؛ **تضمین زنده‌بودن Agent نیست**.
- هیچ آزمون واقعی TLS/SSH، ارسال Telegram یا WSS روی VPS انجام نشده؛ برای تأیید عملیاتی باید تست end-to-end اجرا شود.

## نصب ایمن روی Ubuntu VPS

1. از دیتابیس، فایل `sonar_config.json`، env و گواهی‌های Agent بکاپ خارج از سرور تهیه کنید.
2. ZIP را روی VPS تست استخراج کنید؛ داخل پوشه پروژه، قبل از نصب دستور `bash install.sh --check` را بزنید.
3. برای سیستم نصب‌شده: `sudo bash install.sh --backup` سپس `sudo bash install.sh --update`.
4. `sudo bash install.sh --doctor`، `systemctl status sonar-bot sonar-web` و لاگ‌های سیستم را کنترل کنید.
5. از داخل تلگرام Mini App را باز و دسترسی کاربر معمولی، مدیر، تیم‌ها، سرویس‌ها، اعلان‌ها، صفحات جزئیات و نمودارها را بررسی کنید.
6. خطاهای webhook، HTTPS reverse proxy، نشست Telegram و اتصال WSS را روی زیرساخت خودتان بررسی کنید. اگر staging موفق نبود، از بکاپ رسمی نصب‌کننده به نسخه پایدار قبلی برگردید.

**از باز کردن API روی IP عمومی بدون HTTPS، اجرای آزمایشی مستقیم روی سرور عملیاتی و کپی کلیدهای محرمانه در فایل ZIP خودداری کنید.**
