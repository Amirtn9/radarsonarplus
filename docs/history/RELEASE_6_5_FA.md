# SONAR RADAR Pro v6.5.0 — Installer Resilience + Guide + Reporting (RC)

**وضعیت:** بسته قابل نصب در محیط آزمایشی؛ **تأیید نصب واقعی روی سرور ایران / TLS و VPS عملیاتی هنوز انجام نشده است.**

## تغییرات مبتنی بر سورس 6.4.0

- `agent_bootstrap.py`: شناسایی محیط مقصد (Ubuntu/Debian glibc، amd64/arm64، Python 3.9 تا 3.13، دیسک ≥350 MiB)، بررسی ابزار سیستم، تلاش مستقیم `pip` با timeout و retry محدود، نصب در venv جدید، بسته Wheel مناسب ABI روی سرور اصلی، فایل `requirements.lock` با هش هر Wheel، `manifest.json` با SHA-256، انتقال SFTP روی SSH دارای trusted known_hosts، ادامه فایل `.part` تأییدشده، نصب آفلاین `--no-index --require-hashes`، `pip check` و import smoke، فعال‌سازی venv با نگهداری نسخه قبلی.
- `agent_xray_bridge.py`: fallback آرشیو Xray پین‌شده هنگام شکست دانلود مستقیم در مقصد؛ سرور اصلی باید به GitHub دسترسی داشته باشد. فایل با هش قفل منتشرشده کنترل می‌شود. URL و کلید TLS به بسته Wheel وارد نمی‌شوند.
- `monitor_agent.py`: قابلیت **مصرف فایل Xray تأییدشده محلی** فقط هنگام نصب؛ عملکرد استاندارد Agent، WSS و سایر قابلیت‌های اجرا تغییر نکرده است.
- `agent_deploy.py`: ادغام مسیر نصب جدید با توالی فعلی SSH، هویت اختصاصی Agent و آزمون WSS. بکاپ موقت محدود از Agent script، lock، env، گواهی و unit پیش از تغییر؛ rollback در شکست و پاکسازی بکاپ پس از تأیید سلامت. داده certificate در دیتابیس **فقط پس از نتیجه مثبت واقعی WSS و `xray_ready`** ذخیره می‌شود.
- `core.py`, `admin_panel.py`, `bot_logic_mod/servers.py`: ارسال وضعیت مرحله‌ای نصب برای مدیر در تلگرام؛ راه‌اندازی پس‌زمینه ادامه دارد.
- `notifications.py`: اصلاح دسته‌بندی کانفیگ به «گزارش‌ها»؛ آزمون امکان ارسال پیام در مقصد هنگام ثبت کانال.
- `cronjobs.py`, `bot_logic_mod/servers.py`: اصلاح دوره گزارش ۱۵ دقیقه (بازه ورودیِ ثانیه باید به دقیقه تبدیل شود)، درج کم‌مصرف‌ترین سرور بر اساس آخرین CPU/RAM، درج رتبه کانفیگ (فقط اگر داده‌های رتبه‌بندی موجود باشد). این نتایج اندازه‌گیری زنده را تضمین نمی‌کنند.
- `workspace_ui.py`: سربرگ وضعیت/IP/CPU/RAM/Agent بر اساس آخرین داده ثبت‌شده در سه زیرمنوی ابزارها، تنظیمات و امکانات پیشرفته؛ چیدمان بخشی از دکمه‌ها به دو ستون تغییر کرده است.
- `keyboard.py`, `v6_ui.py`, `pro_portal.py`, `pro_web/guide.html`, `pro_web/static/guide.css`: دکمه راهنما، راهنمای گام‌به‌گام در تلگرام و وب با ظاهر Apple-like و FAQ؛ مسیر `/guide` از سرویس موجود پنل وب ارائه می‌شود. در صورت تنظیم `SONAR_WEBAPP_URL` معتبرِ HTTPS، دکمه باز کردن نسخه وب نمایش داده می‌شود.
- `tests/test_agent_offline_fallback_650.py`: آزمون شبیه‌سازی مسیر مستقیم، timeout، fallback، هش خراب، بسته ناقص، lock خراب، ناسازگاری هدف، cache سالم/آسیب‌دیده.

## آزمون‌های اجراشده در محیط محلی

- بررسی نحوی Python (`compileall`) و Bash (`bash -n`): موفق.
- مجموعه منتخب آزمون‌های رگرسیون: موفق؛ ۱۴ آزمون ویژه نصب آفلاین به مجموعه افزوده شد.
- تست‌های کل پروژه پس از اصلاح انتظار نسخه: ۱۳۴ تست پاس؛ ۴ شکست و ۲ خطای setup ناشی از نبود وابستگی‌های `paramiko` و `telegram` در محیط تست (به‌علاوه ۸ زیرآزمون موفق)؛ این **اثبات سلامت در محیط مقصد نیست**.
- شبیه‌سازی SFTP و timeout: بدون SSH واقعی؛ Hash/manifest با subprocess واقعی روی فایل‌های محلی آزموده شد.

## محدودیت‌های مهم

1. **apt آفلاین کامل نیست:** اگر `python3-venv` یا `openssl`/`curl`/`iproute2` روی سرور مقصد نصب نشده و apt مخزن قابل دسترس ندارد، عملیات با پیام مشخص `SYSTEM_PACKAGES_UNAVAILABLE` متوقف می‌شود. برای چنین سروری باید مخزن apt داخلی یا بسته `.deb` هماهنگ با توزیع فراهم باشد؛ نصب ناقص موفق اعلام نمی‌شود.
2. **اتصال SSH ضروری است:** اگر اتصال SSH سرور اصلی ↔ مقصد به‌طور کامل قطع باشد، انتقال جایگزین هم امکان‌پذیر نیست.
3. **محدودیت محیط:** TLS enrollment، firewall، اجرای systemd، توقف وسط SFTP واقعی و اتصال WSS روی VPS مقصد **اینجا تست نشده‌اند**. استقرار اول با بکاپ و روی VPS آزمایشی انجام شود.
4. **بعضی امکانات UI:** سربرگ ثابت فقط در سه زیرمنوی اصلی پیاده شده، نه همه فرم‌ها و گزارش‌های قدیمی.
5. **پیشرفت دانلود:** پنل مراحل نصب و تغییر مسیر را نمایش می‌دهد؛ درصد لحظه‌به‌لحظه دانلود هنوز ارائه نمی‌شود.
6. **سازگاری:** فقط Ubuntu/Debian glibc با CPU amd64/arm64 و Python 3.9–3.13 در این سازوکار پشتیبانی می‌شود. پشتیبانی از musl، Alpine و CentOS **عمداً غیرفعال** است تا wheel ناسازگار اجرا نشود.
7. **بسته‌های آماده:** کش مرکزی با بررسی SHA روی دیسک اصلی ایجاد می‌شود؛ `SONAR_AGENT_PACKAGE_CACHE_DIR` محل آن را تعیین می‌کند. بسته از قبل دانلود نشده؛ اولین استفاده نیازمند PyPI قابل دسترس از VPS اصلی است.

## استقرار آزمایشی

1. ابتدا از پایگاه داده PostgreSQL، env و گواهی‌های روی VPS بکاپ خارج از سرور تهیه کنید.
2. ZIP نسخه 6.5 را روی VPS **اصلی** مستقر کرده و سرویس ربات را طبق install.sh ارتقا دهید.
3. اتصال SSH و تأیید اثرانگشت مقصد را بررسی کنید.
4. «🧩 نصب/رفع ایجنت» را ابتدا روی یک سرور **آزمایشی** اجرا کنید. مراحل preflight/direct/fallback/transfer/verify/xray/tls/service/wss را ببینید.
5. سلامت نهایی `systemctl status sonar-agent` و `journalctl -u sonar-agent -n 100` و نمایش status در ربات را مستقل بررسی کنید.
6. صفحه راهنما پس از راه‌اندازی پنل وب روی `https://YOUR_HOST/guide` ارائه می‌شود؛ URL عمومی HTTPS پنل را در `SONAR_WEBAPP_URL` بگذارید.

**این انتشار مدعی حذف همه خطاهای محیط ایران نیست.** هدف، مسیر امن جایگزین برای Python Wheel و Xray با هش معتبر و عدم اعلام موفقیت پیش از آزمون WSS است.
