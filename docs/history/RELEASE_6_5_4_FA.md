# SONAR RADAR Pro 6.5.4 — Multi-Agent & Web Application (Release Candidate)

تاریخ: ۲۰ اکتبر ۲۰۲۶. مبنا: نسخه ۶.۵.۳ ارائه‌شده کاربر. این نسخه یک **RC آزمایشی** است و بدون تست Staging و VPS نباید Production Ready نامیده شود.

## تحویل‌شده در سورس

1. **استخر چند Agent ایران**: جدول PostgreSQL برای نودهای پیشنهادی/تأییدشده، امکان لغو رضایت، تأیید مدیر، کنترل مالکیت و سنجش سلامت WSS با استفاده از گواهی و توکن Agent موجود. انتخاب سالم بر اساس RTT WSS، CPU یا مدل ترکیبی انجام می‌شود. fallback تک Agent قدیمی حفظ شده است. نمونه‌های سلامت حداکثر ۵ دقیقه اعتبار دارند؛ برای بیش از ۶۰ نود، Job با cursor گردشی پیش می‌رود.
2. **نصب چندتایی Agent**: انتخاب حداکثر ۱۲ VPS ایران در یک درخواست؛ Job مجزا برای هر سرور مدیر، مراحل preflight/install/WSS verify؛ پورت ذخیره‌شده یا تصادفی ۲۰۰۰۰–۵۹۹۹۹؛ تلاش محدود مجدد فقط برای تداخل پورت تشخیص داده‌شده، بدون متوقف‌کردن سرویس‌های ناشناس. وضعیت‌هایی نظیر failed/needs_review صریح هستند و باز بودن TCP را موفقیت نصب تلقی نمی‌کنند. **برای SSH متعلق به کاربران دیگر نصب خودکار اجرا نمی‌شود.**
3. **کنترل چند پورت و تشخیص چندمسیره**: فقط مقصد ثبت‌شده با IP عمومی و پورت‌های محدود؛ جداسازی TCP open از تأیید TLS/token؛ آزمون از VPS اصلی و حداکثر سه Agent ایران با action جدید و محدود `probe_public_tcp`. نتایج با برچسب «احتمال ایران‌اکسس»، «در دسترس از اصلی»، «شواهد ناکافی» یا «عدم‌دسترسی از نقاط بررسی‌شده» نمایش داده می‌شوند. **تشخیص قطعی اینترنت ملی/قطع کامل ادعا نمی‌شود**؛ CheckHost مستقل به‌صورت API یکپارچه پیاده نشده است.
4. **وب‌سایت مستقل و Mini App**: رابط Apple-inspired فارسی با hamburger، پنج دسته پایین صفحه، حالت روشن/تاریک، داشبورد سرور با عقربه واقعی CPU/RAM/Disk، نمودار تاریخچه، و نشان خفاش؛ Swap با مقدار N/A نمایش داده می‌شود چون Agent آن را نمی‌سنجد. تازگی داده مشخص است؛ Poll ۱۵ثانیه‌ای، نه streaming زنده.
5. **ورود امن وب**: کد هشت‌دقیقه‌ای یک‌بارمصرف از گفت‌وگوی خصوصی ربات؛ هش در PostgreSQL، کوکی ۸ساعته Secure/HttpOnly/SameSite=Strict، CSRF، محدودیت Origin و حفظ مکانیزم اصلی Telegram Mini App initData. HTTPS با `SONAR_WEB_ORIGIN` لازم است.
6. **عملیات وب واقعی**: افزودن سرور با تعیین الزامی IR/EXT و اطلاعات SSH، افزودن کانفیگ و لینک اشتراک (ثبت در وضعیت Pending)، عملیات تأییدی حذف سرور، مانیتور سرویس HTTP/TCP و قوانین هشدار موجود پنل، مدیریت استخر Agent. از متدهای موجود ذخیره‌سازی و سهمیه کاربر استفاده شده؛ ثبت به معنی تست یا نصب موفق نیست.
7. **راهنمای وب**: مطالب جدید آموزش چند Agent، سنجش چند مسیر، ورود مستقل وب، حریم خصوصی و محدودیت‌ها در `/guide` و `DEPLOY_6_5_4_FA.md`.

## حفاظت معماری

- **بایت‌به‌بایت یکسان با ۶.۵.۳**: `ws_client.py`, `ssh_support.py`, `agent_deploy.py`, `database.py`, `access_policy.py`, `agent_runtime.lock.json`, `pro_scoring.py`.
- **تغییر محدود**: `monitor_agent.py` فقط افزوده‌شدن probe عمومی/محدود TCP؛ `core.py` و `tunnel_logic.py` فقط انتخاب Agent از استخر پیش از بازگشت به جریان قدیمی. **قواعد balancer تونل، احراز هویت WSS و TLS قبلی بازنویسی نشده‌اند.**
- **افزوده شده**: `monitor_fleet.py`, `fleet_api.py`, `fleet_bot.py`, `web_login.py`, `web_operations.py`, `pro_web/static/next.css`, `next.js`, `web_ops.js` و تست‌های جدید.
- **دیگر تغییرات**: `bot.py`, `pro_portal.py`, `keyboard.py`, چند handler مربوط به ایجاد/انتخاب سرور، پنل HTML/CSS/JS، راهنما، manifest، متادیتای نسخه، `.env.example`.

## آزمون‌های اجراشده و حدود اعتماد

- مجموعه کامل `pytest` در محیط فعلی: **۱۷۲ موفق، ۴ ناموفق، ۲ خطای آماده‌سازی و ۸ subtest موفق**. ۶ مورد ناموفق/خطا مرتبط با نصب نبودن `paramiko` و `python-telegram-bot` هستند و **نه تأیید خرابی عملیات VPS**. مجموعه کامل در محیط مجهز به dependencies با Staging واقعی تکرار شود.
- آزمون‌های جدید نسخه ۶.۵.۴ شامل انتخاب نود تأییدشده، مهلت سلامت پنج دقیقه‌ای، حق دسترسی، رد IP خصوصی، اعتبارسنجی کد وب، و محدودیت اختیارات admin اجرا و موفق شدند.
- بررسی Python `compileall`، `bash -n`، `node --check`، تمام فایل‌های ZIP و Manifest پیش از بسته‌بندی انجام شده است.
- تست نصب SSH/agent روی VPS واقعی، TLS/WSS واقعی، PostgreSQL Migration روی دیتابیس production، سرویس تلگرام واقعی، تغییر پورت در فایروال ابری، replayهای چندگانه و تست Browser End-to-End **اجرا نشده‌اند**.

## محدودیت‌های باقی‌مانده، بدون ادعای خلاف واقع

- وب‌سایت هنوز **همه** امکانات تلگرام را ندارد: خرید واقعی اشتراک و اتصال پرداخت، کنترل تمام دستورات SSH، تغییر IP با ثبت دوباره گواهی TLS، مدیریت کامل هم‌گروهی، و تنظیم همه کرون‌جاب‌ها هنوز باید به‌صورت افزایشی به سرویس‌های اصلی متصل و در Staging تأیید شوند.
- روش سوم «سرعت» نیازمند معیار throughput واقعی و کنترل حجم مصرفی است و **پیاده نشده**؛ سه سیاست کنونی «latency»، «load» و «balanced» هستند.
- نصب روی VPS کاربران دیگر بدون مجوز مالک عمداً ممنوع است و پیشنهاد Agent لزوماً اجازه SSH دادن به مدیر نیست.
- اشتراک‌گذاری نود در مقیاس عمومی نیازمند طراحی سهمیه تست/محاسبه هزینه و بازبینی حفاظت حملات حجمی است؛ نسخه فعلی برخی semaphoreها را استفاده می‌کند اما تست بار اجرا نشده است.
- برای شناسایی دقیق Iran Access به یک یا چند نقطه مستقل قابل‌اعتماد در داخل/خارج و policy تطبیق نیاز است؛ TCP-only تشخیص قطعی محسوب نمی‌شود.
- «Live» نشان‌دهنده تازه‌ترین نمونه ثبت‌شده DB است؛ حالت real-time streaming نیازمند قرارداد metric افزایشی Agent است. swap، temperature و per-interface throughput هنوز N/A می‌مانند.
- نشست ویب ۸ساعته؛ کد ورود یک‌بارمصرف است نه توکن API دائمی. کلید دائمی در مرورگر صادر نمی‌شود.
- در صورت برخورد port و شکست WSS، سرویس قبلی ممکن است به بازبینی انسانی نیاز داشته باشد؛ عملیات rollback هنوز روی VPS واقعی تأیید نشده است.

## پیش از استقرار

راهنمای `DEPLOY_6_5_4_FA.md` را بخوانید. ابتدا backup و clone دیتابیس Staging، سپس کنترل `SONAR_WEB_ORIGIN` و HTTPS reverse proxy، شروع bot و API با config یکسان، WSS agent/TLS smoke و تست ارتباطات دو VPS ایران. اگر صحت Postgres Migration، داده، Agent و Telegram در Staging تأیید نشد، نسخه ۶.۵.۳ را عملیاتی نگه دارید.
