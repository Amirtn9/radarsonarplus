# راهنمای راه‌اندازی نسخه آزمایشی Sonar Radar Pro 6.5.4

## پیش‌شرط: محیط Staging

**این بسته هنوز روی VPS واقعی، PostgreSQL عملیاتی و تلگرام واقعی تست نشده است؛ نصب مستقیم روی محیط عملیاتی توصیه نمی‌شود.**

۱. از PostgreSQL با `pg_dump` و از فایل‌های `sonar_config.json`، کلیدهای رمزنگاری موجود در SONAR_STATE_DIR، گواهی Agent و فایل‌های SSH known_hosts بکاپ بگیرید؛ بازیابی را روی Staging تست کنید.
۲. یک کپی از دیتابیس و یک hostname HTTPS آزمایشی آماده کنید. ربات و پنل از **همان** PostgreSQL و state رمزنگاری مورداعتماد استفاده کنند، نه کپی جداگانه با رمز متفاوت.
۳. در فایل محیطی سرویس API مقدار `SONAR_WEB_ORIGIN=https://your-host.example` را با URL واقعیِ **بدون اسلش انتهایی** تنظیم کنید؛ از HTTP عمومی یا hostname آزمایشیِ نادرست استفاده نکنید. هیچ کلید/رمزی داخل ZIP قرار ندهید.
۴. از روی کد دستورهای `bash install.sh --check` و در صورت تأیید سیاست پشتیبان‌گیری `sudo bash install.sh --update` را روی Staging اجرا کنید؛ سپس `sudo bash install.sh --doctor` را بررسی کنید.
۵. بررسی کنید `pro_portal.py` پشت reverse proxy معتبر HTTPS قرار گرفته و پورت backend فقط در لوپ‌بک `127.0.0.1` در دسترس باشد. برای استفاده از mini app تلگرام نیز HTTPS لازم است.
۶. در گفت‌وگوی **خصوصی** ربات گزینه «پنل گرافیکی» را بزنید؛ کد هشت‌دقیقه‌ای فقط یک‌بار پذیرفته می‌شود. وب‌سایت نشست هشت‌ساعته با کوکی Secure/HttpOnly و CSRF دارد. کد را به کسی ندهید و آن را در URL یا لاگ قرار ندهید.

## استخر Agent ایران

- برای افزودن سرور، ایران/خارج را حتماً مشخص کنید. فقط سرورهای ایران قابل انتخاب برای استخر هستند.
- مالک یک سرور می‌تواند آن را **پیشنهاد** دهد؛ مدیر اصلی پس از رضایت مالک و بررسی، آن را **تأیید** می‌کند. فهرست کل سرورهای سایر کاربران در اختیار عموم قرار نمی‌گیرد.
- گزینه «نصب چندتایی» فقط روی سرورهای ایران **متعلق به مدیر** فعال است. از انجام نصب روی SSH دیگران بدون رضایت و مدیریت دسترسی معتبر جلوگیری می‌شود.
- نصب روی هر سرور در یک Job مستقل انجام می‌شود. پورت حالت `stored` همان تنظیم فعلی است؛ حالت `automatic` یک پورت ۲۰۰۰۰–۵۹۹۹۹ انتخاب می‌کند و حداکثر ۲ بار دیگر فقط در صورت `AGENT_PORT_CONFLICT` تلاش می‌کند. این پورت باید در فایروال host/cloud مجاز باشد و پس از نصب، در DB ثبت شود.
- پورت TCP باز کافی نیست؛ Agent باید با TLS/WSS و توکن اختصاصی سالم پاسخ دهد. شکست مرحله آخر به `needs_review` می‌رود؛ سرویس دیگری خودکار متوقف نمی‌شود.
- الگوریتم‌های مدیر: `latency` (RTT درخواست WSS از میزبان اصلی، نه ICMP ping)، `load` (CPU گزارش‌شده)، `balanced` (ترکیب RTT و CPU). معیار «سرعت» throughput مستقل ندارد، زیرا اندازه‌گیری upload/download واقعی Agent در این نسخه کامل نیست.
- استخر فقط نودهای تأییدشده با نمونه سلامت معتبر در ۵ دقیقه اخیر را انتخاب می‌کند؛ نبود نود سالم به مسیر تک‌نود قدیمی بازمی‌گردد. نسخه‌های قدیمی Agent ممکن است عمل `probe_public_tcp` را نداشته باشند و پاسخ «شواهد ناکافی» داده شود.
- نصب نسخه جدید ربات به‌تنهایی کد Agent قبلی را روی VPS مقصد عوض نمی‌کند. برای تست چندمسیره از ایران، Agentهای منتخب باید با روش نصب/repair موجود به‌روز شوند.

## تشخیص دسترسی ایران/خارج

- endpoint چندمسیره، فقط IP عددی عمومیِ سرور ذخیره‌شده و پورت‌های محدود را از میزبان اصلی و تا ۳ Agent تأییدشده بررسی می‌کند.
- اگر خارج قطع و ایران سالم بود: **احتمال محدودشدن دسترسی از خارج**، نه تشخیص قطعی Iran Access.
- اگر هر دو ناموفق بودند: **عدم دسترسی از نقاط بررسی‌شده**، نه لزوماً خاموشی کامل سرور.
- نتیجه بر اساس TCP است؛ TCP بسته همیشه معنی قطع ICMP، خراب بودن سایت یا قطعی کامل نیست.

## پنل وب

- وب اپ دارای منوی همبرگری، پنج تب موبایلی، حالت روشن/تاریک، تاریخچه و نمایش عقربه‌ای داده‌های ذخیره‌شده CPU/RAM/Disk است. نرخ Poll به‌صورت دوره‌ای است و **stream حقیقی real-time نیست**. Swap چون Agent فعلی اندازه‌گیری نمی‌کند N/A است.
- ثبت سرور و کانفیگ در API با همان پایگاه‌داده و محدودیت مالکیت قبلی انجام می‌شود؛ رمز SSH سمت سرور با سرویس اصلی رمزنگاری می‌شود. ثبت سرور معادل نصب Agent نیست و ثبت کانفیگ معادل تست موفق نیست.
- عملیات حساس حساب، خرید اشتراک/درگاه پرداخت، تغییر IP همراه مهاجرت TLS، حذف گروه‌های همکار و تمام ابزارهای کنترلی ربات هنوز **در وب پیاده‌سازی کامل نشده‌اند**. آن‌ها فعلاً باید از مسیرهای موجود و قابل‌ممیزی تلگرام استفاده شوند؛ این نسخه را «برابری کامل وب با ربات» ننامید.
- تنظیمات WSS/TLS، اسکریپت SSH و بالانسر تونل‌های موجود بدون بازنویسی باقی مانده‌اند؛ تغییرات افزایشی به انتخاب Agent، API و یک اکشن خواندنی Agent محدود شده‌اند.

## چک‌لیست تست Staging

- نصب روی ۲ VPS ایرانِ متعلق به مدیر، یکی با پورت اشغال و دیگری آزاد؛ بدون stop کردن سرویس ناشناس.
- اجرا و تکرار نصب با قطع SSH، WSS، DNS و restart سرویس، همراه با rollback و کنترل گواهی‌ها.
- کد وب یک‌بارمصرف، منقضی، invalid، CSRF و مالکیت resource؛ بررسی محرمانه‌نماندن رمز در لاگ‌ها.
- ارسال/رد پیشنهاد Agent از کاربر دوم و بررسی عدم دسترسی به سرورهای غیرمجاز.
- بارگذاری مانیتورینگ/کانفیگ‌ها با ۲ Agent سالم، ۱ Agent قطع و در شرایط سرور «احتمال ایران‌اکسس»؛ مقایسه با check-host مستقلی که کاربر مجاز است به آن مراجعه کند.
- قبل از انتشار اصلی: آزمون کامل API در مرورگر واقعی، PostgreSQL واقعی، Telegram handler registration، SSH host verification، WSS TLS، فایروال provider و آزمون Load.
