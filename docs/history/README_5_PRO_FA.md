# Sonar Radar Pro 5.0 | راهنمای نسخه توسعه‌یافته

این نسخه ادامه مستقیم بسته `4.3-secure-fixed` است و **سیستم فعلی مدیریت سرور، کانفیگ، سابسکریپشن، پرداخت و بکاپ** را حفظ می‌کند. امکانات جدید در ماژول‌های `pro_*` افزوده شده‌اند.

> **قبل از استقرار:** این بسته روی محیط آفلاین بررسی شده و هیچ تست واقعی اتصال به Telegram، PostgreSQL عملیاتی، Agentهای شما یا نصب service/systemd انجام نشده است. **در محیط staging تست کنید و بدون بکاپِ بازیابی‌شده وارد تولید نشوید.** موفق‌شدن تست‌های آفلاین به معنای تضمین نصب در محیط شما نیست.

## قابلیت‌هایی که **هنوز استقرار یا توسعه بیشتر لازم دارند**

- **Mini App بدون دامنه عمومی HTTPS فعال نمی‌شود.** پنل و API تحویل شده‌اند، ولی ثبت دامنه، DNS، گواهی TLS، فایروال و انتشار روی سرور شما انجام نشده است.
- **تست چند منطقه‌ای به حضور دو ایجنت واقعی، قابل اعتماد و پیکربندی‌شده نیاز دارد.** بدون آن، ممکن است فقط یک نقطه آزمایش شود یا هیچ آزمایشی اجرا نشود.
- **ارتباط Agentها در نصب قدیمی الزاماً TLS ندارد.** گزینه `SONAR_WS_TLS=1` و قابلیت گواهی TLS در ایجنت اضافه شده، اما ایجاد و توزیع گواهی، ترمیم همه ایجنت‌ها، اتصال معکوس Agentها و mTLS به استقرار مجزا نیاز دارند.
- **صف کارها** در این نسخه محدودکننده و منصفانه‌تر شده، ولی **صف پایدار توزیع‌شده (Redis/Celery)، failover چند نمونه‌ای و اجرای job با تضمین تحویل** هنوز پیاده‌سازی نشده است.
- **هوشمندی تحلیل** بر پایه قواعد و همبستگی آماری است، نه هوش مصنوعی/LLM یا تشخیص قطعی علت قطعی.
- **RBAC تیمی** برای امکانات Pro و API اجرا می‌شود؛ مجوزهای مدیر/ناظر به شکل فراگیر روی *تمام* عملیات قدیمی ربات تعمیم داده نشده‌اند.
- **Audit** عملیات جدید را ثبت می‌کند. لاگ‌گیری کامل تمام مسیرهای قدیمی مدیریت/پرداخت نیازمند توسعه تکمیلی است.
- **Premium** در امکانات قبلی طرح‌ها و پرداخت باقی مانده؛ قیمت‌گذاری جدید، پرداخت خودکار، webhook مالی و سهمیه‌بندی تجاری ویژگی‌ها به درگاه واقعی/تصمیم تجاری وابسته‌اند و اضافه نشده‌اند.
- قوانین اتوماسیون عمداً فقط اعلان و گزارش دارند؛ راه‌اندازی اجرای خودکار `reboot`/SSH بدون تأیید انسانی ایمن نیست و پیاده‌سازی نشده است.
- گزارش PDF خروجی لحظه‌ای از آخرین داده‌هاست؛ هنوز پیوست نمودارهای پیشرفته و SLA قراردادی داخل PDF وجود ندارد.


> **به‌روزرسانی بررسی نصب (۱۱ اکتبر ۲۰۲۶):** `install.sh` در بسته اصلاح‌شده با نصب مرحله‌ای، گزارش خطا، بکاپ PostgreSQL، حفظ تنظیمات و بازگشت نسخه کد هنگام شکست جایگزین شده است. اجرای واقعی روی سرور عملیاتی همچنان آزمایش نشده؛ شرح جزئیات در `INSTALL_AUDIT_FA.md` است.

## ۱) نصب ربات و ارتقای پایگاه‌داده

**پیش‌نیازها:** سرور لینوکسی مبتنی بر Debian/Ubuntu، Python 3.10+، PostgreSQL، اتصال اینترنت برای نصب pip و پکیج‌ها. از دیتابیس، `secret.key`، تنظیمات و فایل‌های سفارشی بکاپ بگیرید.

```bash
# فایل ZIP را به یک مسیر موقت انتقال داده و Extract کنید.
cd /path/to/extracted-sonar
sudo bash install.sh
# گزینه 2: ارتقا از نسخه قبلی (بکاپ جداگانه ضروری است)
# گزینه 1: نصب تازه
```

در **حالت ارتقا**، نصب‌کننده تلاش می‌کند توکن و شناسه مدیر فعلی را حفظ کند. فایل `sonar_config.json` داخل ZIP عمداً **بدون توکن و شناسه واقعی** تحویل شده تا اطلاعات محرمانه از بسته منتشر نشود؛ اگر ربات را در مسیر جدید بدون Installer اجرا می‌کنید، توکن خود را در تنظیمات امن همان سرور قرار دهید.

پس از بالا آمدن ربات، `post_init` ساختارهای `pro_*` را در یک تراکنش اضافه می‌کند. **اسکریپت راه‌اندازی با خطای مهاجرت متوقف می‌شود** تا بخش‌های جدید نیمه‌فعال نشوند. هیچ جدول قبلی در این مهاجرت حذف نمی‌شود.

### نکات مانیتورینگ خودکار

- پیش‌فرض **خاموش** است و با `⚙️ تنظیمات هشدارها` فعال می‌شود. با حداکثر ۱۰ کاربر در هر اجرای ۳۰دقیقه‌ای، ۸ کانفیگ برای هر کاربر و حداکثر دو نود، بار مدیریت می‌شود. ۲ نود فقط وقتی موجود باشند به کار می‌روند؛ مفهوم «داخل/خارج» نیاز به تنظیم نود واقعی دارد.
- موفق‌بودن تست تنها نمونه‌ای از وضعیت اتصال است؛ درباره تمام مسیرها نتیجه قطعی نمی‌دهد.
- پاک‌سازی تاریخچه پس از ۳۰ روز به صورت خودکار انجام می‌شود.
- برای کنترل تعداد تست‌ها حجم محدود تعیین شده؛ این نسخه جایگزین تست بار تولیدی و تنظیم ظرفیت براساس زیرساخت نیست.

## ۲) راه‌اندازی Mini App (اختیاری و مستقل از Bot)

مخزن حاوی `pro_portal.py`, `pro_web/index.html`, `pro_web/static/` و `install_web_panel.sh` است. وب‌پنل از **initData امضاشده تلگرام** استفاده می‌کند، نه توکن قابل نمایش در پیام یا URL. API روی 127.0.0.1:8090 گوش می‌کند. مستقیماً این پورت را به اینترنت متصل نکنید.

```bash
sudo bash /opt/radar-sonar/install_web_panel.sh
# Nginx HTTPS reverse proxy را با WEB_PROXY_EXAMPLE.conf تنظیم و دامنه واقعی را جایگزین کنید.
# در فایل /etc/sonar-bot.env این سطر را اضافه کنید:
SONAR_WEBAPP_URL=https://your-domain.example/
sudo systemctl restart sonar-bot
sudo systemctl status sonar-web
```

`SONAR_WEBAPP_URL` باید نشانی **HTTPS عمومی** باشد. در غیر این صورت دکمه بازشدن مستقیم Mini App نمایش داده نمی‌شود و ربات راهنمای فعال‌سازی نشان می‌دهد. وب‌پنل به‌صورت مستقل از ربات اجرا می‌شود؛ نبود پنل، عملکرد بات را متوقف نمی‌کند. اعتبار `initData` حداکثر پنج دقیقه است و پس از پایان، کاربر باید پنل را از داخل تلگرام دوباره باز کند.

**نکته:** اگر Bot روی همان سرور PostgreSQL نصب شده، `SONAR_DB_POOL_MAX=12` در سرویس وب به جلوگیری از مصرف زیاد اتصال‌ها کمک می‌کند. برای تعداد کاربران بالا، PostgreSQL pool و process workerها باید جداگانه تنظیم شوند.

## ۳) TLS اختیاری برای WebSocket Agentها

پیش‌فرض مسیر قدیمی WS حفظ شده تا ارتقای کد اتصال سرورهای موجود را ناگهانی قطع نکند. **WS ساده روی اینترنت عمومی توصیه نمی‌شود**.

در سرویس Agent روی هر نود، با صدور گواهی معتبر سازگار با دامنه/IP مقصد:

```ini
SONAR_AGENT_TLS_CERT=/path/to/fullchain.pem
SONAR_AGENT_TLS_KEY=/path/to/privkey.pem
```

سپس روی **سرویس Bot** (پس از TLS-enabled شدن همه نودها):

```ini
SONAR_WS_TLS=1
```

این تنظیم در نسخه حاضر **سراسری** است، نه برای هر نود. پس قبل از فعال‌سازی، تمام Agentهای استفاده‌شده باید WSS و گواهی معتبرِ قابل راستی‌آزمایی داشته باشند. اگر نودها TLS ندارند، ارتباطشان را روی شبکه خصوصی یا تونل امن محدود کنید و پورت Agent را فقط برای IP مجاز باز بگذارید. فعال‌سازی WS و WSS همزمان برای نودهای مختلف هنوز نیازمند طراحی اختصاصی است.

## ۴) تست و عیب‌یابی

```bash
cd /opt/radar-sonar
python3 -m compileall -q .
python3 -m pytest -q tests
bash -n install.sh install_web_panel.sh
node --check pro_web/static/app.js # اختیاری
sudo systemctl status sonar-bot
sudo journalctl -u sonar-bot -n 100 --no-pager
sudo journalctl -u sonar-web -n 100 --no-pager
```

در محیط ساخت این ZIP، **۱۸ تست آفلاین از ۱۸ تست گذشت**. مجموعه شامل ۷ تست ۴.۳، آزمون HMAC تلگرام و جعل داده، کنترل دسترسی API با دیتابیس شبیه‌سازی‌شده، امتیاز، مهاجرت‌های افزایشی، یکپارچگی دکمه/Job و امن‌بودن HTML/PDF است. PDF آزمایشی به تصویر تبدیل و چیدمان فارسی آن بررسی شد. `node --check` و `bash -n` و `compileall` نیز موفق بودند.

**آزمون‌های باقی‌مانده برای تیم عملیات:** مهاجرت روی کپی PostgreSQL واقعی، تست تمام دکمه‌های قدیمی و جدید با Telegram Bot API، اتصال به Agentهای واقعی، اندازه‌گیری منابع CPU/RAM تحت بار، تست بکاپ/Restore، تست گواهی WSS، تست وب پنل در موبایل تلگرام، بررسی نقش‌ها و تست rollback. نتیجه آفلاین جای این‌ها را نمی‌گیرد.
