**وضعیت:** نسخهٔ آزمایشی Release Candidate؛ **برای VPS اصلی/Production تأیید نشده است.**

پایهٔ کد از هستهٔ ۶.۵.۴ و اصلاحات بستهٔ RC1 نسخهٔ ۶.۶ گرفته شده است؛ این نسخه بازنویسی پروژه نیست. معماری مستقل مسیریابی تونل‌ها و بالانسر اصلی آن تغییر نکرده‌اند.

### تعریف دقیق مصرف

مجموع گزارش‌شده = بایت‌های ارسالی/دریافتی **WebSocket برنامه** + حجم payload دریافت‌شده و قابل‌اندازه‌گیری برخی تست‌ها. حجم Xray subprocess، TLS overhead، retransmit شبکه، سایر نرم‌افزارهای VPS و ترافیک کل کارت شبکه جزو این گزارش نیست. اطلاعات مربوط به ترافیک بین نمونه‌برداری‌ها و restart بدون نمونهٔ آخر ممکن است ناقص باشند؛ این گزارش برای حسابداری رسمی پهنای‌باند کافی نیست.

**بازنشانی** دورهٔ جدید در دیتابیس می‌سازد و مقدار تاریخی قبلی را حذف نمی‌کند. بازنشانی مصرف واقعی سرویس‌دهنده یا فایروال انجام نمی‌دهد.

### شرایط لازم برای Relay

1. حداقل یک Agent ایران قبلاً با نصب معتبر، WSS/TLS و توکن ثبت شده و از مرکزی در دسترس باشد.
2. Agent باید به آدرس عمومی مقصد روی پورت SSH ثبت‌شده دسترسی داشته باشد؛ اگر پورت ۲۲ در تمام مسیرها بسته است، Relay کمکی نمی‌کند.
3. سرور مقصد باید در دیتابیس ثبت شده باشد، یا در فرآیند افزودن با Agentهای محدود و دارای تأیید بررسی شود.
4. فهرست مجاز پورت Relay به‌طور پیش‌فرض `22,2022,2222` است. برای پورت سفارشی، متغیر `SONAR_AGENT_RELAY_PORTS` روی **خود Agent** تنظیم و سرویس را با احتیاط restart کنید. پورت‌های عمومی غیرمجاز برای محدودکردن سوءاستفاده رد می‌شوند.
5. هر سرور SSH باید fingerprint مستقل و معتبر داشته باشد. از تأیید خودکار host key نامعلوم استفاده نمی‌شود.

## ج) خروجی بررسی‌ها

- بررسی نحوی Python، Bash و JavaScript و تست‌های هدفمند جدید/قبلی با موفقیت اجرا شده‌اند.
- مجموعهٔ اصلی `pytest` در محیط آزمایشی به علت نبودن **`paramiko`** و **`python-telegram-bot`** کامل اجرا نشده است؛ این تست‌ها **PASS محسوب نمی‌شوند**.
- هیچ اتصال زنده‌ای به VPS کاربران، درگاه Telegram، PostgreSQL واقعی یا دامنهٔ HTTPS صورت نگرفته است.
- نتیجهٔ آزمون‌های WSS و SSH محلی نباید به موفقیت در محیط واقعی تعبیر شود.

**حکم انتشار:** تحویل کد برای بازبینی و نصب آزمایشی؛ تا تأیید تمام سناریوهای عملیاتی، نسخهٔ پایدار ننامید.
