# نسخه ۶.۹.۷ — اعتبارسنجی گزارش ممیزی و اصلاح قابلیت اطمینان

تاریخ: 2026-11-09. مبنای بررسی نسخه ۶.۹.۶، commit `2cee7d4` است.

## نتیجه بررسی مستقل

- شکست CI روی Python 3.10 و 3.11 در محیط محلی بازتولید شد: ۴۴۹ موفق، یک شکست و ۲۸ skipped. علت، mock ناقص SSL در تست fallback IPv4 بود؛ نه خاموش بودن اعتبارسنجی TLS برنامه. تست اکنون context واقعی با بررسی گواهی و hostname دارد. job نسخه 3.12 همان اجرای تاریخی موفق بود؛ بنابراین شکست کل workflow به معنی شکست تمام jobها نبود. stack trace خصوصی اجرای تاریخی در دسترس نبود.
- اجرای واقعی CI همچنین رقابت دو پردازش هنگام فعال‌سازی WAL را آشکار کرد: یکی از صف‌ها با `database is locked` راه‌اندازی نمی‌شد و تنها ۵۰ رکورد از ۱۰۰ رکورد باقی می‌ماند. تست مستقل با قفل کنترل‌شده نیز پیش از اصلاح شکست خورد. راه‌اندازی اکنون قفل موقت را تا پنج ثانیه retry می‌کند؛ timeout عملیات عادی همچنان ۱۰۰ ms است.
- هنگام قطع PostgreSQL و قفل موقت SQLite، batch حافظه‌ای واقعاً حذف می‌شد. تست ابتدا شکست خورد؛ worker اکنون batch محدود را برای تلاش مجدد نگه می‌دارد و تعداد آن در health دیده می‌شود. محدودیت ظرفیت و احتمال از دست رفتن داده در خرابی هم‌زمان همه رسانه‌ها همچنان برقرار است.
- ثبت هم‌زمان لاگ در middleware می‌توانست event loop را تا پایان fsync متوقف کند. تست کندی این موضوع را تأیید کرد. ثبت اکنون در thread انجام می‌شود و پاسخ همچنان منتظر تأیید ثبت می‌ماند.
- نبود اجرای مرورگر در CI تأیید شد. هر چهار سناریوی مرورگر اکنون در job مستقل با PostgreSQL و HTTPS آزمایشی اجرا می‌شوند. fixture دیتابیس تصادفی مستقل می‌سازد؛ شبکه بیرونی، Telegram، SSH و پاک‌سازی میزبان شبیه‌سازی می‌شوند و عملیات مخرب واقعی اجرا نمی‌شود.

## بازتولیدپذیری و آزمون‌ها

- وابستگی‌های مستقیم و انتقالی Python برای محیط CI لینوکس و نسخه‌های 3.10، 3.11 و 3.12 در `requirements/ci-py*.lock` همراه SHA-256 قفل شده‌اند. این فایل‌ها ادعای پوشش همه سیستم‌عامل‌ها یا وابستگی اختیاری S3 ندارند. نصب CI با `--require-hashes` است.
- Playwright با package-lock قفل شده؛ Actions و Node به نسل Node 24 ارتقا یافته‌اند. JUnit، نسخه وابستگی‌ها و شواهد مرورگر به‌عنوان artifact ذخیره می‌شوند.
- هسته‌های Xray طبق فایل قفل موجود، از انتشار رسمی دانلود و با checksum بررسی می‌شوند؛ هر دو هسته در تست‌های واقعی محلی استفاده شدند.
- هر **۴۸۳ تست** روی هر سه Python 3.10، 3.11 و 3.12 با PostgreSQL واقعی و Xray واقعی موفق شد؛ هیچ تستی skipped نشد. PostgreSQL محلی نسخه ۱۷ بود؛ workflow از نسخه ۱۶ استفاده می‌کند.
- هر چهار سناریوی Playwright شامل راهنما در ۱۸ ترکیب viewport/text-size، ورود و CSRF، تله‌متری و مدیریت لاگ با موفقیت اجرا شدند. syntax، compilation، dependency check، preflight، manifest و ساخت آرشیو انتشار نیز موفق بودند.
- تست ارتقا، ساخت schema نسخه ۶.۹.۵، خطای SQL در میانه migration، rollback و اجرای مجدد را همراه حفظ credential رمز‌شده بررسی می‌کند. این آزمایش خاموشی واقعی میزبان دیتابیس نیست.
- دو پردازش مستقل مجموعاً ۱۰۰ لاگ در صف مشترک ثبت می‌کنند و با `os._exit` بسته می‌شوند؛ بازگشایی صف هر ۱۰۰ شناسه یکتا را بازیابی می‌کند.

## محدودیت‌های باقی‌مانده

تأیید عملیاتی نصب و ارتقا روی VPS مشتری، Telegram واقعی، SSH نودهای واقعی، خرابی سیستم‌عامل و سنجش بار واقعی انجام نشده است. نتیجه محلی تست‌ها به‌تنهایی ادعای سبز بودن اجرای GitHub نیست؛ وضعیت اجرای هر commit باید در Actions همان commit دیده شود. عدد ۴۷۸ گزارش نسخه قبلی مربوط به اجرای محلی Python 3.12 بود و تأیید ماتریس CI محسوب نمی‌شود.

نبود LICENSE تأیید شد؛ انتخاب مجوز حقوقی نیازمند تصمیم مالک است و مجوز دلخواهی اضافه نشده است. اتصال PasarGuard همچنان در این مخزن یافت نشد. حذف انتخابی journal مشترک، دسترسی به نود خاموش و پاک‌سازی مسیرهای سفارشی همچنان محدودیت مستند دارند؛ حذف عمومی journal راه‌حل قابل قبول نیست. Agent و Backend هر دو ۶.۹.۷ و پروتکل همچنان ۲ هستند؛ Agent نصب‌شده باید جداگانه به‌روز شود.
