# برنامه مرحله‌ای ارتقای تجربه پنل

## مرحله اول: داشبورد، کارت سرور و منوی کناری

- [x] **۱. داشبورد:** چهار کارت آماری سرورها، کانفیگ‌ها، مانیتورها و رخدادها مستقیماً بخش مربوطه را باز می‌کنند؛ با صفحه‌کلید نیز قابل استفاده‌اند.
- [x] **۲. کارت سرور:** وضعیت پایش، CPU/RAM/Disk، صفر واقعی، داده ناموجود/قدیمی و WSS حفظ شده‌اند. نتیجه مستقل آخرین بررسی SSH و زمان آخرین موفقیت ثبت‌شده به کارت اضافه شد؛ تلاش جدید یا خطای اتصال، موفقیت قبلی را پاک نمی‌کند. بدون بررسی، وضعیت «بررسی‌نشده» است؛ WSS جای SSH را نمی‌گیرد.
- [x] **۳. منوی کناری:** شش گروه باز و بسته‌شونده برای حساب، منابع، پایش، Agentها، همکاری و تنظیمات؛ ذخیره ترجیح گروه‌ها در مرورگر، پشتیبانی صفحه‌کلید و بازشدن گروه صفحه فعال. مجوزهای فعلی دکمه‌ها حفظ می‌شوند.
- [x] **۴. Agentها:** کارت مشترک صفحه Agentها و بالانسر با نام/شناسه/منطقه، ارتباط، TLS، WSS، Heartbeat موفق و تازگی، تأخیر و CPU معتبر (شامل صفر)، نسخه و بیلد و مسیر جزئیات/رفع مشکل. ثبت گواهی با تأیید TLS در heartbeat اخیر متفاوت است؛ داده قدیمی و مرورگر آفلاین زنده نشان داده نمی‌شوند. نسخه فقط با بررسی گروهی موجود دریافت می‌شود؛ کارت درخواست جداگانه نمی‌فرستد و نود قطع‌شده «قدیمی» فرض نمی‌شود.
- [x] **۵. بالانسر:** پنجره اختصاصی اسلایدر و ورودی دقیق ۰ تا ۱۰۰۰، وضعیت ذخیره/خطا و جلوگیری از ارسال تکراری؛ مرتب‌سازی پیش‌نویس با Drag & Drop یا دکمه بالا/پایین برای صفحه‌کلید/لمس. ذخیره گروهی در یک تراکنش با تشخیص تعارض انجام می‌شود و اولویت‌ها از صفر شماره‌گذاری می‌شوند. مسیر مرکزی ثابت است؛ تغییر ترتیب سلامت، تأیید یا رضایت مالک را تغییر نمی‌دهد. اولویت صفر در مرتب‌سازی و API حفظ می‌شود.
- [x] **۶. رخدادها:** فیلتر وضعیت/شدت/نوع و شناسه منبع/بازه شروع، جست‌وجو، مرتب‌سازی و صفحه‌بندی با شمارش منطبق و بازیابی صفحه خارج از محدوده اضافه شد. Timeline از رویدادهای واقعی چرخه رخداد، یادداشت‌ها و اقدامات ثبت‌شده ساخته می‌شود؛ برای رخداد قدیمی تاریخچه جعل یا backfill نمی‌شود.
- [x] **۷. جزئیات سرور و SSH:** تب‌های نمای کلی، منابع، اتصال، تاریخچه و عملیات، با لینک مستقیم و Back/reload و صفحه‌کلید اضافه شدند. بررسی SSH صریح، زمان تلاش/پایان و آخرین موفقیت را جداگانه ثبت می‌کند؛ احراز هویت، کلید ناشناخته/تغییریافته، شبکه و نیاز sudo از هم جدا هستند. بازکردن یا جابه‌جایی تب‌ها SSH اجرا نمی‌کند؛ تاریخچه هر بخش حداکثر ۲۰ نمونه اخیر را صریح نشان می‌دهد.
- [x] **۸. کانفیگ‌ها:** فیلتر سلامت/نوع/پروتکل/برچسب/علاقه‌مندی و جست‌وجو، مرتب‌سازی تأخیر/امتیاز ۰ تا ۱۰/زمان بررسی/نام و خلاصه شمارش منطبق با تمام فیلترها اضافه شد. تست‌نشده، خطای محیط، شکست کانفیگ، صف تست و منبع اشتراک جدا هستند؛ مقادیر ناموجود بهترین مقدار یا صفر فرض نمی‌شوند. نتیجه پیش از ویرایش لینک برای نسخه جدید معتبر نشان داده نمی‌شود.
- [x] **۹. دکمه‌ها و آیکون‌ها:** الگوی مشترک SVG/عنوان و رنگ معنایی معمولی، اصلی و مخرب؛ وضعیت انتظار، موفقیت و خطا برای عملیات متصل، جلوگیری از ثبت تکراری فرم مانیتور و حفظ تأیید عملیات مخرب. انصراف موفقیت محسوب نمی‌شود و کنترل غیرفعال ثابت، در حال اجرا نمایش داده نمی‌شود.
- [x] **۱۰. موبایل و Mini App:** فرم‌ها و پنجره‌ها با عرض و ارتفاع قابل مشاهده تطبیق می‌یابند؛ Safe Area، صفحه‌کلید شبیه‌سازی‌شده، متن درشت، منوی پایین، محصورکردن فوکوس منو و بازگشت تلگرام برای پنجره/منو/صفحه بررسی می‌شوند. اجرای کلاینت واقعی تلگرام در این محیط تأیید نشده است.
- [x] **۱۱. جست‌وجوی سراسری:** سرور، کانفیگ، Agent و رخداد همراه مانیتورها و نتایج مدیریتی مجاز دسته‌بندی می‌شوند؛ پنجره صفحه‌کلید، debounce، رد پاسخ قدیمی، بارگذاری/بدون نتیجه/خطا و تلاش دوباره و لینک مستقیم جزئیات دارد. تطبیق Agent مشترک از نام/IP خصوصی مالک دیگر استفاده نمی‌کند؛ فهرست عمومی فقط پس از رضایت مالک و تأیید مدیر قابل جست‌وجو است.
- [x] **۱۲. راهنمای متناسب با صفحه:** راهنمای بازشونده متناسب با صفحه، نقش و شواهد موجود مانند SSH، داده قدیمی و آفلاین؛ آموزش مرتبط با API مجاز موجود داخل پنل باز می‌شود. راهنما probe خودکار یا مجوز عملیات جدید ایجاد نمی‌کند.
- [x] **۱۳. فوری — فرم افزودن مانیتور:** تداخل Flex با Grid اختصاصی تک‌ستونه تا عرض ۶۲۰ و دو‌ستونه در نمایشگر بزرگ‌تر رفع شد؛ آدرس یک ردیف کامل دارد، عنوان‌ها به کنترل‌ها متصل‌اند و دکمه و ورودی‌ها اندازه قابل استفاده دارند. آزمون مرورگر `browser_monitor_form.cjs` چیدمان ۳۲۰، ۳۶۰، ۳۹۰، ۴۳۰، ۸۲۰ و ۱۴۴۰ را در دو پوسته، آدرس طولانی، اعتبارسنجی عددی، ثبت با صفحه‌کلید و نگاشت واقعی فیلدهای ذخیره‌شده بررسی می‌کند. این آزمون به اجرای کامل مرورگر اضافه شده است. تست‌ها روی fixture محلی Chromium انجام می‌شوند؛ اجرای کلاینت واقعی تلگرام ادعا نمی‌شود.

## آزمون‌های مرحله اول

سناریوی مرورگر `scripts/browser_product_stage1.cjs` ورود با امضای Mini App، ناوبری کارت‌های آماری با صفحه‌کلید، حفظ وضعیت گروه‌ها پس از بارگذاری مجدد، مقادیر صفر و ناموجود، داده قدیمی، قطع مرورگر و عرض‌های ۳۲۰ تا ۱۴۴۰ را در دو پوسته بررسی می‌کند. این سناریو به اجرای کامل مرورگر اضافه شده است.

تست PostgreSQL فهرست منابع نیز بازگشت مقادیر واقعی CPU/RAM/Disk از API و عدم افشای رمز، کلید SSH و توکن Agent را بررسی می‌کند. نتیجه اجرا و شناسه کامیت هر مرحله در پاسخ همان مرحله گزارش می‌شود.

اعتبارسنجی مرحله اول: ۶۸۳ تست و ۸ زیرتست روی Python 3.12 موفق بودند و هر ۱۰ مجموعه مرورگر پاس شدند. پس از اصلاح عرض کارت‌ها، سناریوی اختصاصی کارت‌ها و منو دوباره موفق اجرا شد. تست API نیز مقادیر نامعتبر `NaN`، بی‌نهایت و درصد خارج از محدوده را بررسی می‌کند؛ این مقادیر به داده ناموجود تبدیل می‌شوند تا پاسخ JSON خراب نشود.

وضعیت نهایی: هر ۱۳ مورد در محدوده پیاده‌سازی و آزمون محلی این سند تکمیل شده‌اند. اعتبارسنجی هر مرحله و محدودیت‌های محیط در ادامه ثبت شده است.

اعتبارسنجی مورد ۱۳ در ۱۶ نوامبر ۲۰۲۶: روی Python 3.12.14 و PostgreSQL 17، هر ۶۸۳ تست و ۸ زیرتست موفق بود؛ تست ناموفق یا Skip وجود نداشت (۵ هشدار). هر ۱۱ مجموعه مرورگر Chromium، شامل ۱۲ ترکیب عرض/پوسته فرم جدید، موفق بود. lint خطاهای نام تعریف‌نشده، syntax، preflight، manifest، نقشه پروژه و ساخت آرشیو نیز بررسی شدند. این نتیجه اجرای محلی است؛ وضعیت GitHub Actions، استقرار VPS و کلاینت واقعی تلگرام را تأیید نمی‌کند.

## اعتبارسنجی مرحله دوم: Agentها و بالانسر

۱۶ نوامبر ۲۰۲۶: مجموعه Python 3.12 با PostgreSQL 17 و دو Xray قفل‌شده، ۶۸۴ تست و ۸ زیرتست موفق، بدون شکست یا Skip و با ۵ هشدار داشت. آزمون PostgreSQL جدید rollback تمام تغییرات پس از خطای ردیف دوم، رد درخواست کاربر غیرمدیر، حفظ حریم خصوصی نودهای مشترک، داده عددی نامعتبر، اولویت صفر و تعارض درخواست هم‌زمان را بررسی می‌کند. آزمون هم‌زمانی پس از تکمیل، جداگانه نیز موفق اجرا شد.

هر ۱۲ مجموعه مرورگر موفق بود. سناریوی `browser_fleet_priorities.cjs` تازگی و انقضای heartbeat، تفکیک ثبت گواهی از TLS تأییدشده، CPU صفر، رضایت مالک، دریافت گروهی نسخه، اسلایدر، ورودی عددی، جابه‌جایی ماوس/صفحه‌کلید، انصراف، شکست ذخیره، جلوگیری از ثبت تکراری، حفظ ترتیب پس از reload و ثابت‌بودن مسیر مرکزی را بررسی می‌کند. عرض‌های ۳۲۰، ۳۹۰، ۸۲۰ و ۱۴۴۰ در هر دو پوسته با تصویر واقعی بررسی شدند؛ تست کنتراست نام Agent و خوانایی مسیر مرکزی نیز اضافه شد. داده fleet فقط در fixture محلی و برای این سناریو ساخته می‌شود تا تست‌های قبلی مستقل بمانند.

اطلاعات نسخه در حافظه همان صفحه، همراه زمان بررسی موجود نگهداری می‌شود؛ برای داده تازه باید دکمه بررسی نسخه را استفاده کرد. هیچ ادعای اتصال TLS/WSS به سرور خارجی، استقرار VPS یا آزمایش کلاینت واقعی تلگرام وجود ندارد؛ شواهد مرورگر از fixture مصنوعی با API و پایگاه داده واقعی محلی است. در پایان مرحله دوم، رخدادها، جزئیات سرور و SSH و مراحل بعدی باقی بودند؛ وضعیت مرحله سوم در ادامه آمده است.

## مرحله سوم: رخدادها، جزئیات سرور و SSH

مهاجرت افزایشی **۲۱ / operational_history**، پس از مهاجرت ۲۰، ثبت تراکنشی چرخه رخدادها را برای تمام نویسنده‌های فعلی با trigger مشترک اضافه می‌کند. تغییر واقعی وضعیت، تکرار و شدت ثبت می‌شود؛ رویدادهای پیش از مهاجرت ساخته نمی‌شوند. یادداشت‌ها و اقدام‌های موجود نیز با محدوده مالک و پاک‌سازی متن محرمانه خوانده می‌شوند. Timeline صفحه‌بندی مستقل دارد و شمارش فهرست از همان snapshot فیلترشده به دست می‌آید.

جدول مستقل بررسی‌های SSH فقط از دکمه بررسی صریح تغذیه می‌شود. آخرین تلاش با آخرین موفقیت متفاوت است؛ نتیجه نامشخص یا شکست جدید، موفقیت قبلی را حذف نمی‌کند. `SUDO_REQUIRED` به معنی اتصال برقرار با نیاز به مجوز مدیریتی است، نه خطای احراز هویت. Viewer اجازه شروع بررسی ندارد. هیچ کلید ناشناخته‌ای خودکار پذیرفته نمی‌شود و مقدار رمز، متن فرمان یا خطای خام در شواهد ذخیره و نمایش داده نمی‌شود.

تب‌های سرور، عملیات و ترمینال موجود را حفظ می‌کنند. انتخاب تب در URL می‌ماند، Back/reload و لینک مستقیم کار می‌کنند؛ منبع شناسه فعال سرور نیز برای لینک مستقیم و عملیات یکسان شد. منابع و نمودارها در تب منابع، بررسی اتصال و اعتماد در تب اتصال و عملیات صریح در تب عملیات در دسترس‌اند. داده تاریخچه محدود به آخرین ۲۰ مورد هر بخش است؛ این محدودیت در رابط نوشته شده است.

محدوده اعتبارسنجی همچنان محیط محلی PostgreSQL/Chromium و SSH مصنوعی fixture است؛ اتصال SSH به VPS خارجی، استقرار و اجرای کلاینت واقعی تلگرام ادعا نمی‌شود. Timeline داده عملیاتیِ همراه رخداد است و با حذف رخداد پاک می‌شود؛ پاک‌سازی و نگهداری لاگ‌های قبلی تغییر نکرده است. بخش اقدام‌هایی که از audit خوانده می‌شود تابع نگهداری همان audit است.

اعتبارسنجی نهایی مرحله سوم در ۱۶ نوامبر ۲۰۲۶: **۶۸۷ تست و ۸ زیرتست** روی Python 3.12/PostgreSQL 17 و هسته‌های Xray قفل‌شده موفق شدند؛ شکست و Skip صفر، با ۵ هشدار. هر **۱۳ مجموعه مرورگر** موفق شد و سناریوی اختصاصی جدید پس از آخرین اصلاحات دوباره اجرا شد. فیلتر/شمارش/صفحه خارج از محدوده، Timeline و یادداشت‌های owner-scoped، عدم افشای متن محرمانه، مهاجرت قدیمی/هم‌زمان، تفکیک خطاهای SSH و مجوز فنی پیش از probe بررسی شدند. تب‌ها و فیلترها در عرض‌های ۳۲۰، ۳۹۰، ۸۲۰ و ۱۴۴۰، دو پوسته و با زمان محلی تهران بررسی تصویری و اجرایی شدند. lint نام‌های تعریف‌نشده، سازگاری نحوی Python 3.10، نحو JS/Shell، preflight، manifest، نقشه پروژه و ساخت release نیز بررسی شدند. اجرای Python 3.10/3.11 یا GitHub Actions برای این مرحله ادعا نمی‌شود.

## مرحله چهارم: فیلتر کانفیگ و جست‌وجوی سراسری

مهاجرت **۲۲ / config_catalog** زمان تغییر واقعی لینک/نوع را، بدون ساخت زمان برای داده قدیمی، ثبت می‌کند و index خواندن آخرین کار تست را اضافه می‌کند. سنجش قدیمی و خطای کارِ پیش از ویرایش برای نسخه تازه معتبر محسوب نمی‌شوند. خطای جدید اجرای تست، «خطای محیط سنجش» است و به شکست کانفیگ تبدیل نمی‌شود؛ اندازه‌گیری جدیدتر می‌تواند جای آن را بگیرد. پروتکل فقط از نوع و پیشوند قابل تشخیص استخراج می‌شود؛ وجود Hysteria2/TUIC در فیلتر، پشتیبانی عملیاتی را تأیید نمی‌کند.

فهرست، شمارش کل و خلاصه سلامت از همان snapshot و همان فیلترها خوانده می‌شوند. مرتب‌سازیِ داده ناموجود در انتهاست؛ امتیاز پیش‌فرض کانفیگ تست‌نشده به امتیاز واقعی تبدیل نمی‌شود. فیلترها در URL و Back/reload حفظ می‌شوند و صفحه خارج از محدوده به آخرین صفحه معتبر برمی‌گردد. آدرس پیش‌فرض `/configs` بدون پارامتر اضافی حفظ شده است.

جست‌وجو حداکثر ۱۰ نتیجه از هر دسته می‌دهد و برای جست‌وجوی عادی نیازی به بارگیری ماژول مالی ندارد. لینک کانفیگ، رمز SSH، توکن و نشانی خصوصی Agent دیگران در نتایج بازگردانده نمی‌شود. نتایج کاربر/سفارش همچنان به capability مدیریتی موجود وابسته‌اند. لینک مستقیم رخداد پنجره Timeline را باز می‌کند؛ Agent متعلق به کاربر به تب اتصال و مانیتور به کارت/تاریخچه مربوط منتقل می‌شود. نوسازی مانیتورها هنگام نوشتن فرم، فوکوس یا پیش‌نویس را نمی‌گیرد.

اعتبارسنجی محلی ۱۶ نوامبر ۲۰۲۶: **۶۸۹ تست و ۸ زیرتست** روی Python 3.12/PostgreSQL 17 و Xrayهای قفل‌شده موفق شدند؛ شکست و Skip صفر و ۵ هشدار. هر **۱۴ مجموعه مرورگر** موفق شد. سناریوی جدید فیلترهای ترکیبی، خلاصه و صفحه‌بندی، داده ناموجود، URL/Back/reload، دسته‌بندی نتایج، عدم افشای لینک/فضای دیگر، ورود مستقیم، صفحه‌کلید، debounce، پاسخ دیررس، بازیابی خطا و حفظ پیش‌نویس را پوشش می‌دهد. عرض‌های ۳۲۰، ۳۹۰، ۸۲۰ و ۱۴۴۰ در دو پوسته با تصویر واقعی بررسی شدند. lint، syntax، سازگاری نحوی Python 3.10، preflight، manifest، نقشه پروژه و build نیز بررسی شدند.

این مرحله آزمون زنده پروتکل‌ها یا اتصال خارجی تازه اجرا نمی‌کند. استقرار VPS، کلاینت واقعی تلگرام، اجرای Python 3.10/3.11 و وضعیت GitHub Actions برای این مرحله تأیید نشده‌اند.


## مرحله پنجم: دکمه‌ها، موبایل و راهنمای زمینه‌ای

دکمه‌های عملیاتی از آیکون و رنگ معنایی مشترک استفاده می‌کنند و نام دسترس‌پذیر آن‌ها حفظ می‌شود. فرم مانیتور هنگام ثبت قفل می‌شود؛ خطا، موفقیت و انصراف مسیرهای جدا دارند. حذف بدون سابقه مالی نیز پیش از درخواست موجود، تأیید صریح دارد.

منوی سریع فوکوس را در خود نگه می‌دارد و پس از بسته‌شدن به کنترل آغازکننده برمی‌گرداند. Back شبیه‌سازی‌شده تلگرام ابتدا پنجره، سپس منو و سپس صفحه را می‌بندد. پنجره‌ها با visual viewport و Safe Area تنظیم می‌شوند. راهنمای صفحه از داده نمایشی و capability موجود استفاده می‌کند و آموزش مجاز را بدون خروج از پنل باز می‌کند؛ هیچ probe تازه‌ای خودکار اجرا نمی‌شود.

سناریوی `browser_mobile_context.cjs` حالت انتظار/خطا/موفقیت، جلوگیری از ثبت تکراری، انصراف حذف بدون DELETE، فوکوس، SSH و داده قدیمی، قطع اینترنت، راهنمای نقش مشاهده‌گر در فضای تیمی fixture، متن درشت و ۱۵۶ ترکیب صفحه/عرض/پوسته را بررسی می‌کند. آزمون Mini App و صفحه‌کلید شبیه‌سازی است؛ آزمون دستگاه واقعی، استقرار VPS، اتصال SSH خارجی و وضعیت GitHub Actions در این مرحله تأیید نشده‌اند.

اعتبارسنجی نهایی مرحله پنجم در ۱۶ نوامبر ۲۰۲۶: **۶۸۹ تست و ۸ زیرتست** روی Python 3.12/PostgreSQL 17 و Xrayهای قفل‌شده موفق شدند؛ شکست و Skip صفر، با ۵ هشدار. هر **۱۵ مجموعه مرورگر** موفق شد؛ مجموعه پیشین ۴۶۴ حالت واکنش‌گرایی/پوسته در ۲۹ نما و سناریوی تازه ۱۵۶ ترکیب دیگر را پوشش داد. بررسی نقش مشاهده‌گر در فضای تیمی fixture الزامی بود و اجرا شد. تصاویر روشن/تاریک موبایل و دسکتاپ و پنجره جست‌وجو با ارتفاع صفحه‌کلید شبیه‌سازی‌شده تولید و بررسی شدند. lint، نحو Python/JS/Shell و سازگاری نحوی Python 3.10، preflight نصب، manifest، نقشه پروژه و ساخت release نیز موفق بودند. اجرای واقعی Python 3.10/3.11 ادعا نمی‌شود.
