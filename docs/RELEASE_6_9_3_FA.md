# نسخه ۶.۹.۳: مینی‌اپ، سنجش کانفیگ و آموزش تعاملی

## تغییرات ورود

- مینی‌اپ از دکمهٔ ربات با دادهٔ **امضاشدهٔ تلگرام** خودکار وارد می‌شود. اگر CDN تلگرام کند یا مسدود باشد، payload اصلی راه‌اندازی از fragment استاندارد تلگرام خوانده و همچنان روی سرور اعتبارسنجی می‌شود.
- `initDataUnsafe`، آیدی داخل URL و پارامتر `admin=true` هیچ‌کدام اعتبار ورود یا نقش مدیریت ایجاد نمی‌کنند.
- تبادل امضای معتبر با کوکی Secure/HttpOnly و CSRF انجام می‌شود. امضای منقضی یا دست‌کاری‌شده همچنان رد می‌شود؛ محدودیت عمر امضا کاهش امنیتی نداشته است.
- دامنه HTTPS خود مینی‌اپ برای ورود و درخواست‌های دارای CSRF معتبر پذیرفته می‌شود، حتی اگر دامنه وب مستقل متفاوت باشد. Origin نامرتبط رد می‌شود.
- ورود **وب مستقل** همچنان به کد یک‌بارمصرف صادرشده در گفت‌وگوی خصوصی و Origin پیکربندی‌شده نیاز دارد. دکمه‌های «مینی‌اپ (ورود خودکار)» و «کد ورود وب‌سایت» در حساب از هم جدا شده‌اند.
- بنر خطای قدیمی پس از ورود موفق پاک می‌شود؛ فرم کد وب در یک راه‌اندازی معتبر مینی‌اپ نمایش داده نمی‌شود.

## سنجش کانفیگ‌های با خروجی WireGuard

گزارش کاربر مربوط به VLESS/VMess/Trojan بود که **در سمت سرور** از WireGuard خارج می‌شوند. این‌ها کانفیگ مستقیم WireGuard نیستند و نباید پروتکل ورودی‌شان تغییر کند.

سنجش قبلی به یک مقصد HTTP گوگل وابسته بود. نسخه جدید:

1. مقصدهای مستقل HTTPS از GStatic، Cloudflare و Google را امتحان می‌کند.
2. پس از اولین پاسخ ۲۰۴ معتبر، برای نمونه‌های Ping همان مقصد موفق را دوباره استفاده می‌کند.
3. یک بودجه کلی حدود ۱۸ ثانیه و سقف تعداد درخواست دارد؛ TLS همچنان بررسی می‌شود و پاسخ ۲۰۰ نامرتبط یا captive portal موفقیت محسوب نمی‌شود.
4. `socks5h` برای حل نام در مسیر پراکسی و `--noproxy ''` برای جلوگیری از دورزدن تست توسط متغیر محیطی NO_PROXY استفاده می‌شود.
5. خرابی هسته، نبود Xray یا قطع ارتباط با Agent، «سنجش نامشخص» است؛ وضعیت کانفیگ به‌اشتباه Fail نمی‌شود.
6. تست سبک، همگانی، اشتراک، تست سنگین و دکمه‌های قدیمی از مسیر تاریخچه و اعلان مشترک استفاده می‌کنند؛ نتایج زمان‌بندی‌شده نیز شمارنده سلامت داشبورد را به‌روز می‌کنند.
7. در گزارش ناموفق، نام کانفیگ و توضیح امن DNS/TCP/TLS/timeout نمایش داده می‌شود؛ متن خام استثنا و لینک محرمانه نمایش داده نمی‌شود.

**محدودیت:** خود ۵ کانفیگ عملیاتی کاربر و سرور خروجی WireGuard در دسترس نبودند. سناریوی مسدودبودن مقصد اول و موفقیت مقصد مستقل در تست بازتولید شد، ولی سلامت همه کانفیگ‌های واقعی بدون اجرای مجدد روی Agent کاربر تأیید نمی‌شود. پس از ارتقا، Agent همان نود را هم به‌روز و تست همه ۱۱ کانفیگ را تکرار کنید.

## آموزش جدید

مسیر ربات: **آموزش و راهنمای ربات**. مسیر وب: `/guide`.

- ۱۰ دسته و ۸۷ درس برای کاربران عادی؛ با مدیریت، مجموعاً ۱۴ دسته و ۱۱۶ درس.
- فرهنگ ۳۴۰ عنوان دکمه از منابع واقعی رابط ربات تولید می‌شود؛ عنوان‌های ثابت و الگوهای عنوان پویا را پوشش می‌دهد و قابل جست‌وجو است. `…` جای نام/شماره مورد انتخابی است.
- شروع کار، سرورها، نصب و بازیابی Agent، کانفیگ و اشتراک، کیفیت، رخداد، اعلان، کرون‌جاب، کانال، سرویس HTTP/TCP، حساب و همکاری جداگانه توضیح داده شده‌اند.
- آموزش انتشار امضاشده Agent، canary، rollout/rollback، مدیریت کاربران، توکن API، webhook، سیاست سلامت و backup مخصوص مدیر است.
- محتوای مدیریتی **روی سرور** از خروجی عمومی/کاربر عادی حذف می‌شود؛ صرفاً با CSS پنهان نشده است. پاسخ شخصی نیز `private, no-store` است.
- HTML/CSS/JavaScript واکنش‌گرا، فونت وزیر معمولی و ضخیم به‌صورت محلی با مجوز OFL، مسیر تصویری SVG، جست‌وجوی فارسی و پشتیبانی از کاهش حرکت سیستم اضافه شده است.
- برای استفاده بدون وب نیز دسته‌های آموزش در خود ربات صفحه‌بندی شده‌اند.

ساخت دوباره فرهنگ دکمه‌ها پس از تغییر کیبوردها:

```bash
python scripts/build_guide_catalog.py
```

## اعلان و زمان‌بندی کانفیگ‌ها

مسیر ربات: **تنظیمات ← اعلان کانفیگ‌ها** یا `/configalerts`.
مسیر مینی‌اپ/وب: **تنظیمات ← اعلان و زمان‌بندی کانفیگ‌ها**.

| گزینه | رفتار |
| --- | --- |
| کلید اصلی | خاموش‌کردن ارسال اعلان و ایجاد تست/گزارش جدید **همین بخش**؛ تست دستی و برنامه‌های مستقل قدیمی جدا هستند |
| قطعی | پس از تعداد شکست متوالی تعیین‌شده از یک برچسب سنجش؛ پیش‌فرض ۲ |
| بازیابی | نخستین موفقیت پس از ثبت وضعیت قطع؛ موفقیت تکراری پیام تکراری تولید نمی‌کند |
| تغییر امتیاز | اختلاف با آخرین امتیاز مرجع از ۱۰۰؛ پیش‌فرض ۲۰ واحد و حداقل فاصله ۱۵ دقیقه |
| تست خودکار | اختیاری، پیش‌فرض خاموش؛ فاصله شروع دسته‌ها از ۲ تا ۱۴۴۰ دقیقه |
| گزارش دوره‌ای | اختیاری، پیش‌فرض خاموش؛ آخرین نتایج و امتیازها هر ۱۵ دقیقه تا یک هفته |
| ساعت سکوت | شروع/پایان ۰ تا ۲۳، با پشتیبانی از عبور از نیمه‌شب؛ پیش‌فرض منطقه Asia/Tehran |
| کانفیگ بی‌صدا | لیست شناسه‌های متعلق به فضای کاری؛ از ارسال فوری آن موارد جلوگیری می‌کند |
| مقصد پیام | از کانال/گروه/موضوع‌های موجود استفاده می‌کند؛ گزارش در دسته گزارش، هشدار در دسته قطعی و در نبود مقصد معتبر تلاش خصوصی |

اعلان «فوری» به معنی پردازش صف معمولاً حداکثر حدود ۱۵ ثانیه **پس از ثبت نمونه** است، نه تست شبکه در هر ثانیه. زمان تشخیص به فاصله تست، صف Agent و آستانه شکست بستگی دارد. تحویل به تلگرام می‌تواند به دلیل سکوت، محدودیت یا خطای شبکه دیرتر انجام شود.

هر دسته خودکار حداکثر ۸ کانفیگ از هر مالک را به‌صورت چرخشی تست می‌کند؛ برای ۱۱ کانفیگ یک دور کامل به بیش از یک دسته نیاز دارد. اجرای موازی محدود است. گزارش دوره‌ای تست تازه ایجاد نمی‌کند و حداکثر ۲۵ ردیف را در پیام نشان می‌دهد؛ فهرست کامل در پنل است.

cursor مصرف نمونه، وضعیت انتقال و outbox در PostgreSQL نگه داشته می‌شوند. ثبت وضعیت و پیام در یک تراکنش است؛ شکست نوشتن صف، cursor و انتقال وضعیت را هم برمی‌گرداند. نمونه‌های تاریخی پیش از ارتقا به‌عنوان هشدار جدید بازپخش نمی‌شوند. ارسال به تلگرام at-least-once است؛ در قطع فرایند دقیقاً پس از پذیرش پیام توسط تلگرام، تکرار نادر همچنان ممکن است. کلید یکتای رویداد از ایجاد عادی پیام تکراری جلوگیری می‌کند.

مجوز حساب، قواعد عمومی اعلان، ساعت سکوت عمومی و تنظیمات این بخش هنگام تحویل بررسی می‌شوند. خاموش‌کردن یک گزینه روی پیام‌های هنوز تحویل‌نشده نیز اعمال می‌شود. آستانه این بخش، آستانه **اعلان** است؛ رخدادهای قدیمی Pro سیاست خود را حفظ می‌کنند.

## ارتقای نصب موجود

1. بکاپ معتبر دیتابیس و کلید رمزنگاری متناظر تهیه کنید.
2. از checkout خارج از مسیر نصب زنده:

```bash
git pull --ff-only
bash install.sh --check
sudo bash install.sh --update
```

3. هنگام شروع Bot/Web، مهاجرت افزایشی **۱۲ / config_alerts** خودکار اجرا می‌شود؛ schemaهای منتشرشده قبلی و داده‌های کانفیگ تغییر مخرب ندارند.
4. از صفحه نود مانیتورینگ، **نصب/رفع Agent** را اجرا کنید تا فایل `monitor_agent.py` نسخه ۶.۹.۳ روی خود نود هم نصب شود. به‌روزکردن فقط ربات مرکزی، منطق تست Agent قدیمی را عوض نمی‌کند.
5. مینی‌اپ را از دکمه خود ربات دوباره باز کنید و ورود خودکار، شمارنده و تست تازه را بررسی کنید. وب مستقل باید همچنان کد بخواهد.
6. ابتدا یک اعلان آزمایشی در محیط staging و مقصد مجاز اجرا و سپس زمان‌بندی دلخواه را روشن کنید. کلیدهای گزارش/تست پیش‌فرض خاموش‌اند تا ترافیک ناخواسته ایجاد نشود.

بسته‌های وابستگی جدیدی به runtime اضافه نشده‌اند؛ آموزش از CDN فونت استفاده نمی‌کند. `AGENT_PROTOCOL` تغییری نکرده و داده‌های رمز‌شده نیازمند تبدیل نیستند.

## اعتبارسنجی

- مجموعه pytest با PostgreSQL واقعی و دیتابیس‌های تصادفی مستقل اجرا شد؛ **۳۸۲ تست موفق، ۸ هشدار deprecation و ۸ subtest موفق**؛ در اجرای نهایی هیچ تست ناموفق یا skip وجود نداشت.
- تست‌های جدید: fallback مقصد HTTPS، عدم دورزدن SOCKS، Unknown برای نبود runtime، راه‌اندازی بدون CDN، تطابق فرهنگ دکمه‌ها، کنترل نقش، تنظیمات نامعتبر، قطعی/بازیابی/امتیاز، cooldown، خاموشی و سکوت هر کانفیگ، rollback صف و عدم دست‌کاری کانفیگ مالک دیگر.
- Chromium روی HTTPS محلی و حساب‌های ساختگی: ورود خودکار با SDK مسدود، ذخیره واقعی تنظیمات با کوکی و CSRF، جداسازی آموزش مدیر/کاربر، جست‌وجوی فارسی WireGuard، صفحه موبایل و دسکتاپ و فرم دستی وب. گواهی self-signed فقط در این fixture محلی پذیرفته شد؛ بررسی TLS برنامه و نصب تغییر نکرد.
- صحت وابستگی، نحو Python/Bash/JavaScript، manifest و ساخت قطعی ZIP نیز کنترل می‌شود.
- اتصال واقعی به Telegram API، تست دستگاه واقعی Telegram و مسیر WireGuard کاربر بدون اعتبارنامه و نود آزمایشی اجرا نشده‌اند. آزمون مرورگر جای تأیید آن مسیرهای عملیاتی را نمی‌گیرد.

اسکریپت اختیاری smoke مرورگر `scripts/browser_feature_smoke.cjs` به Playwright و Chromium نصب‌شده و یک سرور **محلی آزمایشی** با داده ساختگی نیاز دارد؛ عمداً مقصد عمومی/عملیاتی را نمی‌پذیرد.
