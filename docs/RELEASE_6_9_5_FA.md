# نسخه ۶.۹.۵ — سازگاری هسته و اصلاح تشخیص کانفیگ

## نتیجه بررسی

در ۱۷ آبان ۱۴۰۵، مسیر رسمی `XTLS/Xray-core/releases/latest` به **v26.10.31** هدایت شد. قفل قبلی پروژه **v26.3.27** بود؛ تصویر کاربر نیز هسته **26.1.31** را در v2rayN نشان می‌داد. نسخه رابط v2rayN با نسخه هسته متفاوت است.

تفاوت نتیجه گوشی/رایانه و نود به‌تنهایی خرابی کانفیگ را ثابت نمی‌کند. بدون لینک واقعی و دسترسی به نود مشتری، علت قطعی پنج شکست گزارش‌شده تعیین نشده است. موارد زیر در کد و آزمون‌های مصنوعی تأیید و اصلاح شدند.

## هسته اصلی و سازگاری بدون TLS

هسته اصلی **v26.10.31** است. آرشیوهای x86_64 و aarch64 از انتشار رسمی دریافت و SHA-256 آن‌ها با digest رسمی همان asset تطبیق داده شد. نصب هم در مقصد و هم هنگام انتقال از سرور مرکزی، SHA-256 را کنترل می‌کند. آدرس شناور latest در زمان اجرای Agent دانلود نمی‌شود؛ نسخه بررسی‌شده در lock ثبت شده است.

**نکته مهم:** هسته جدید، VLESS روی آدرس عمومی با `security=none` و `encryption=none` را رد می‌کند. این ناسازگاری با خود binary جدید بازتولید شد. بررسی نسخه‌های پایدار نشان داد **v26.6.27** آن را می‌پذیرد و نسخه‌های v26.7.11، v26.7.28، v26.9.9، v26.9.30 و v26.10.21 همان محدودیت را دارند.

بنابراین Agent دو هسته مجزا نصب می‌کند:

| حالت | انتخاب |
| --- | --- |
| TLS، Reality، VLESS Encryption و سایر پروفایل‌های معمول | v26.10.31 |
| VLESS عمومی صریحاً بدون TLS و بدون encryption؛ یا Trojan بدون TLS | هسته سازگاری v26.6.27 |
| هسته موردنیاز نصب نیست یا اجرای آن شکست می‌خورد | Unknown با کد عیب‌یابی؛ بدون downgrade خودکار همه پروفایل‌ها |

هسته سازگاری در `compat/` نگهداری می‌شود و با نسخه اصلی جایگزین نمی‌شود. Listener سنجش فقط روی loopback قرار می‌گیرد و MPTCP برای پردازش‌های سنجش غیرفعال است. وجود هسته قدیمی یک مصالحه مشخص برای نگه‌داشتن کانفیگ‌های صریحاً plaintext است؛ این راهکار ادعا نمی‌کند همه پروفایل‌ها را هسته جدید اجرا می‌کند یا حمل‌ونقل plaintext را رمزنگاری می‌کند. TLS یا `allowInsecure` به‌صورت عمومی و اجباری تغییر نمی‌کنند. تنظیمات سفارشیِ صریح `SONAR_XRAY_URL/SHA256` همچنان اولویت خود را حفظ می‌کنند.

نسخه نصب‌شده و نسخه موردانتظار هر دو هسته در پاسخ امن `get_stats` گزارش می‌شوند. وجود lock به معنی نصب‌شدن آن نسخه اعلام نمی‌شود. مسیر نصب بدون دسترسی GitHub مقصد، هر دو آرشیو را از مرکز منتقل و در مقصد مجدداً تأیید می‌کند. مهلت provisioning برای نصب دو runtime افزایش یافت.

## اصلاح تبدیل کانفیگ و routing

- در VLESS/Trojan با TLS، اگر SNI نیامده باشد، Host حمل‌ونقل پیش از آدرس اتصال برای SNI استفاده می‌شود؛ اتصال به IP با گواهی دامنه دیگر به‌اشتباه TLS به IP نمی‌زند. SNI صریح تغییر نمی‌کند.
- حالت‌های VMess با TLS خالی، none، false یا true درست تفکیک می‌شوند؛ تنظیمات WS، XHTTP، gRPC و header HTTP در TCP حفظ می‌شوند.
- XHTTP برای Trojan و `multiMode` در gRPC نیز منتقل می‌شود. گزینه‌های XHTTP extra، path، Host، fingerprint و VLESS encryption حفظ می‌شوند.
- پروفایل JSON کامل Xray یک واحد باقی می‌ماند؛ outbounds، DNS، routing و وابستگی زنجیره‌ای آن بدون تبدیل به outbound تکی حفظ می‌شوند. قالب sing-box همچنان از مسیر تبدیل اختصاصی قبلی می‌رود.
- listenerها و API مدیریتی پروفایل روی نود باز نمی‌شوند؛ یک SOCKS محلی کنترل‌شده جایگزین listener قبلی می‌شود و tag ورودی اصلی برای routing حفظ می‌شود.
- قانون ساختگی `geoip:ir/private -> direct` از تست لینک تکی حذف شد؛ ترافیک نباید ناخواسته پراکسی مورد تست را دور بزند.
- نتیجه پروفایل کامل با `measurement_scope=profile_route` مشخص می‌شود: سلامت مسیر انتخاب‌شده توسط routing، سلامت تک‌تک outboundهای پروفایل نیست.

قواعد routing سراسری v2rayN داخل یک لینک URI معمولی وجود ندارند؛ برای بازتولید همان routing، پروفایل کامل JSON لازم است. JSON کامل چندورودی در سنجش از tag اولین ورودی نام‌دار استفاده می‌کند؛ آزمون همه ورودی‌ها یا همه outboundها ادعا نشده است.

## اصلاح معنای نتیجه سنجش

timeout، خطای DNS/TLS مقصد، پاسخ HTTP نامناسب و خطای محلی تست دیگر به‌تنهایی «کانفیگ خراب» تولید نمی‌کنند. Agent نتیجه Unknown به همراه کد و اطلاعات محدود هر مقصد برمی‌گرداند. پاسخ معتبر 2xx/3xx هم قابل قبول است و الزام غیرضروری به دقیقاً HTTP 204 حذف شده است؛ پاسخ 403/500 هنوز مقصد جایگزین را امتحان می‌کند.

گزارش اشتراک تعداد «سالم از این نود / سنجش ناموفق / نامشخص» را نشان می‌دهد و برای Unknown توضیح می‌دهد قطعی کانفیگ تأیید نشده است. Unknown نمونه شکست ساختگی برای history/alert نمی‌سازد؛ در مسیرهای قبلی که آخرین سنجش معتبر را نگه می‌داشتند، همان سیاست حفظ شده است. تعداد زیادی Unknown نیز یک اختلال قابل بررسی در سنجش است و نباید به معنی سلامت قطعی تفسیر شود؛ Agent جدید از صرف شکست HTTP، قطعی تأییدشده تولید نمی‌کند.

مهلت کلی بررسی مقصدها ۲۴ ثانیه، حداکثر هر درخواست ۸ ثانیه و اتصال ۶ ثانیه است. DNS به SOCKS/Xray سپرده می‌شود. NO_PROXY برای سنجش سرعت نیز مسیر پراکسی را دور نمی‌زند. stderr هسته در pipe بدون مصرف انباشته نمی‌شود. مقادیر محرمانه یا خطای خام کانفیگ در پاسخ خطا قرار نمی‌گیرند.

عدد Ping این برنامه زمان درخواست HTTP از نود است؛ برابرشدن آن با عدد v2rayN روی رایانه، با مقصد و مسیر و زمان متفاوت، تضمین نمی‌شود.

## اعتبارسنجی

- **۴۶۴ تست موفق، بدون skipped، ۸ subtest موفق** با PostgreSQL واقعی محلی و هر دو binary تأییدشده؛ ۶۸ warning مربوط به مجموعه آزمون نیز ثبت شد.
- ۱۱ ترکیب URI/VMess شامل WS با/بدون TLS، XHTTP، fingerprint و VLESS Encryption با core مناسب واقعاً `run -test` شدند.
- پنج آزمون عبور واقعی ترافیک محلی: HTTP → SOCKS → VLESS/WS → سرور مقصد، بدون TLS، با TLS و تأیید گواهی مصنوعی (نه allowInsecure)، همین دو حالت با routing سفارشی و outbound پیش‌فرض blackhole، و هسته سازگاری. لاگ سرور عبور واقعی درخواست از پراکسی را تأیید می‌کند.
- نصب واقعی هر دو runtime روی x86_64 و تکرار نصب از cache بدون دانلود آزمایش شد. صحت آرشیو ARM هر دو نسخه بررسی شد؛ اجرای binary ARM روی این میزبان x86_64 آزمایش نشده است.
- آزمون‌های رگرسیون sing-box، Clash، subscription membership، Unknown، مقصد 403/500، DNS/TLS/timeout، جلوگیری از bypass، انتقال offline و حفاظت SNI/TLS موفق شدند.
- compile، syntax Shell/JavaScript، preflight نصب، manifest، سازگاری وابستگی‌ها و ساخت بسته قطعی نیز کنترل شدند.

فرمان آزمون‌های کامل روی محیط آزمایشی اختصاصی:

```bash
SONAR_TEST_XRAY_BIN=/path/to/verified-26.10.31/xray \
SONAR_TEST_XRAY_COMPAT_BIN=/path/to/verified-26.6.27/xray \
SONAR_TEST_DB_DSN='dbname=postgres user=test_admin host=127.0.0.1 port=5432' \
python -m pytest -q --disable-warnings
```

این تست‌ها ارتباط با کانفیگ واقعی مشتری، مسیر اینترنت ایران یا نود عملیاتی را اثبات نمی‌کنند. آزمون مرورگر جدید برای این اصلاح backend اجرا نشده؛ پوسته رابط تنها نسخه و متن گزارش را به‌روز کرده است.

## نحوه اعمال روی سرور واقعی

۱. نسخه ۶.۹.۵ مرکز را با روش ارتقای موجود و backup داده/کلید متناظر نصب کنید. Migration دیتابیس جدیدی برای این اصلاح اضافه نشده است.

۲. روی **هر نودی که تست کانفیگ را انجام می‌دهد**، از بخش سرور، دکمه **«تعمیر Agent و ثبت مجدد TLS»** یا عملیات **«نصب مجدد/به‌روزرسانی Agent»** را اجرا کنید. فقط آپدیت مرکز، سورس و هسته Agent دور را عوض نمی‌کند.

۳. موفقیت provisioning دو هسته و تست WSS را بررسی کنید؛ سپس اشتراک را دوباره سنجش کنید. وضعیت قبلی تا زمان سنجش تازه، شاهد اجرای کد جدید نیست.

استقرار روی سرور مشتری در این محیط انجام نشده است. اگر پس از ارتقای هر دو سمت هنوز Unknown دیده شد، کد خطا، زمان سنجش، نود و وضعیت مقصدهای سنجش لازم است؛ لینک کامل، UUID، رمز و توکن را در گزارش عمومی GitHub قرار ندهید.
