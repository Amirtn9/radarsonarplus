# رادار سونار 4.3 | نسخه اصلاح‌شده امنیتی و پایداری

این بسته مستقیماً بر اساس فایل ZIP ارائه‌شده اصلاح شده است و جایگزین پروژهٔ عمومی گیت‌هاب نیست. کد پروژه، فایل نصب، راهنمای اصلاحات و تست‌های رگرسیون در همین بسته وجود دارند.

## اصلاحات کلیدی

- **ثبت هندلرها:** تابع `get_custom_ws_port` از حالت کامنت خارج و import ماژول `servers` اضافه شد. هندلرهای callback، message و command اکنون به گارد کنترل دسترسی متصل‌اند.
- **ایجنت:** توکن وب‌سوکت تصادفی و مجزا از SSH تولید شده و به‌صورت رمزگذاری‌شده در ستون جدید `servers.agent_token` ذخیره می‌شود. اجرای سرور ایجنت بدون توکن ۳۲ کاراکتری یا بیشتر رد می‌شود. حالت عادی اجرا فقط روی `127.0.0.1` گوش می‌دهد؛ نصب راه‌دور، پس از فعال‌کردن توکن، bind راه‌دور تنظیم می‌کند. درخواست `run_cmd` از وب‌سوکت عمداً غیرفعال است؛ دستورات مدیریتی همچنان از SSH اجرا می‌شوند. سرویس ایجنت با کاربر کم‌دسترسی `sonar-agent` و محدودیت‌های systemd اجرا می‌شود.
- **SSH:** کد خروج فرمان بررسی و connection در مسیر موفقیت یا خطا بسته می‌شود. اعتبارسنجی کلید میزبان پیش‌فرض اجباری است.
- **کنترل مالکیت:** شناسه‌های سرور، گروه، کانال و کانفیگِ callbackها بررسی می‌شوند؛ عملیات مدیر نیازمند شناسه مدیر اصلی است. عملیات گروهی در لحظه اجرا مالکیت هر سرور را دوباره بررسی می‌کنند.
- **سابسکریپشن:** `parent_sub_id` به آیتم‌ها اضافه شده؛ یکتایی لینک به مالک، نوع و ساب مادر وابسته است. تعویض آیتم‌ها در یک تراکنش انجام می‌شود و در دریافت خالی/ناموفق یا تست بدون نتیجه سالم، موارد قبلی حفظ می‌شوند. آپدیت دستی SSH مسدودکننده را حذف کرده و از پردازش async مشترک استفاده می‌کند. ترتیب سمافور به «کاربر، سپس سراسری» اصلاح شد.
- **جاب‌ها:** مانیتورینگ کانفیگ‌های تکی، آپدیت زمان‌بندی‌شده مخازن، ریبوت برنامه‌ریزی‌شده، آپدیت خودکار اشتراک‌های فعال‌شده و انقضای هدایا پیاده‌سازی شدند. عملیات همگانی با اجرای همزمان محدود انجام می‌شود. گزینه آپدیت خودکار اشتراک‌ها به مرکز کرون‌جاب‌ها اضافه شده است.
- **بکاپ:** تهیهٔ دستی و خودکار هر دو PostgreSQL custom `.dump` تولید می‌کنند. بازیابی فایل‌های `.dump` و `.sql` با دسترسی مدیر، محدودیت حجم، فایل موقت امن و بررسی کد خروج ممکن است. کلید Fernet قبل از جایگزینی اعتبارسنجی می‌شود.
- **نصب:** `install.sh` از محتوای همین بسته استفاده می‌کند؛ نسخه دیگری را از اینترنت clone نمی‌کند. نصب تازه رمز پایگاه‌داده تصادفی ایجاد می‌کند و سرویس ربات را با کاربر `sonar-bot` به‌جای root اجرا می‌کند.

## مراحل نصب یا ارتقا

1. **پیش از ارتقا** از PostgreSQL با `pg_dump -Fc`، فایل `sonar_config.json` و `secret.key` بکاپ امن بگیرید. هیچ‌کدام را در گروه یا ریپازیتوری عمومی منتشر نکنید.
2. فایل ZIP را در مسیر مجزا Extract کنید. از مسیر فایل‌های استخراج‌شده، `sudo bash install.sh` را اجرا کنید. این اسکریپت مسیر `/opt/radar-sonar` را جایگزین می‌کند و برای نصب وابستگی‌ها نیازمند اینترنت و دسترسی root است.
3. برای اتصال SSH، fingerprint میزبان‌ها را **از منبع مستقل بررسی** و در `known_hosts` حساب سرویس `sonar-bot` ثبت کنید. در صورت نیاز فقط با آگاهی از ریسک، `SONAR_SSH_TRUST_ON_FIRST_USE=1` را در محیط سرویس تنظیم کنید؛ این حالت امنیت پایین‌تری دارد.
4. **ایجنت‌های قدیمی باید دوباره نصب/Repair شوند**. از منوی مدیر «نصب/رفع ایجنت‌ها» استفاده کنید تا توکن مخصوص هر سرور ساخته و سرویس بدون دسترسی root راه‌اندازی شود. بدون Repair، WS قدیمیِ بدون توکن متصل نمی‌شود؛ آمار ممکن است با SSH fallback در دسترس باشد.
5. **پورت ایجنت** روی فایروال سرور مقصد فقط برای IP ربات قابل دسترس باشد. ارتباط WebSocket نسخه فعلی TLS ندارد؛ برای شبکه‌های ناامن از تونل خصوصی یا TLS reverse proxy استفاده کنید. رمز SSH به‌جای توکن WS ارسال نمی‌شود.
6. در «مرکز کرون‌جاب‌ها» می‌توانید آپدیت خودکار سابسکریپشن‌ها را روشن کنید. مقدار پیش‌فرض آن **خاموش** است تا ارتقا ناخواسته صدها تست جدید اجرا نکند.
7. پس از نصب، وضعیت service را با `systemctl status sonar-bot`, `systemctl status sonar-agent` (روی نود مقصد) و لاگ‌ها کنترل کنید.

## تست‌ها

در محیط توسعه:

```bash
python -m compileall -q .
python -m pytest -q tests
bash -n install.sh
```

نتیجه تست آفلاین روی بسته اصلاح‌شده: **۷ تست پاس شد**. سناریوها شامل احراز هویت WS، جلوگیری از اجرای دستور، کد خروج SSH، تشخیص هندلر معیوب، رعایت سمافور و مالکیت و حفظ کانفیگ‌های قبلی هستند.

**محدودیت اعتبارسنجی:** در این محیط به PostgreSQL عملیاتی، توکن/شبکه واقعی تلگرام و سرورهای هدف دسترسی اجرایی نداشتیم؛ بنابراین استقرار واقعی، مهاجرت SQL، نصب systemd و تمام دکمه‌های رابط به‌صورت end-to-end تست نشده‌اند. قبل از تعویض ربات عملیاتی، یک محیط staging و بکاپ قابل بازیابی الزامی است. این بسته تضمین «صفر خطا» ندارد و نباید بدون آزمون استقرار وارد تولید شود.

## نکات سازگاری و امنیت

- احراز هویت اجباری WS عمداً اتصال ایجنت‌های ناشناس و قدیمی را قطع می‌کند تا مسیر اجرای دستور بدون احراز هویت باز نماند.
- `run_cmd` روی WS دیگر پشتیبانی نمی‌شود؛ کد نگهداری سرورها از SSH استفاده می‌کند.
- fetch سابسکریپشن ایجنت فقط URLهای عمومی HTTPS را می‌پذیرد و دانلود را محدود می‌کند. منابع HTTP یا خصوصی باید با مسیر امن دیگری فراهم شوند.
- اجرای shell از داخل ترمینال ربات هنوز برای **مالک همان سرور** مجاز است؛ این قابلیت پرریسک است. برای حذف کامل آن، هندلر ترمینال را جداگانه غیرفعال کنید.
- بازیابی دیتابیس را در پنجره نگهداری انجام دهید؛ اتصالات فعال ربات ممکن است با جداول در حال بازیابی تداخل کنند.
- اگر ZIP را به شخص دیگری می‌دهید، فایل `sonar_config.json` ممکن است توکن عملیاتی شما را در خود داشته باشد. قبل از اشتراک‌گذاری، آن را حذف یا توکن را تعویض کنید.
