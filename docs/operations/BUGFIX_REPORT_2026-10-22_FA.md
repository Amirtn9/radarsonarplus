# گزارش نهایی رفع خطاهای SONAR RADAR PRO — ۲۲ اکتبر ۲۰۲۶

## خطاهای بررسی‌شده از لاگ‌ها

- `BadRequest` هنگام پاسخ به callback تلگرام.
- `TimeoutError` هنگام تهیه و ارسال ZIP عیب‌یابی.
- تأخیر شدید Event Loop و از دست‌رفتن زمان اجرای jobهای زمان‌بندی‌شده.
- `SSH_CONNECTION_FAILED` در مرحله تأیید اثرانگشت SSH.
- `AGENT_PORT_CONFLICT` هنگام نصب/تعمیر Agent.
- `VENV_CREATE_FAILED` هنگام ساخت محیط مجازی Python.
- قطع عادی WSS که نباید به tracebackهای تکراری تبدیل شود.

## اصلاحات اعمال‌شده

1. پاسخ callbackهای حساس به زمان از helper امن مشترک استفاده می‌کند؛ callback منقضی‌شده نباید عملیات اصلی را متوقف کند.
2. مسیرهای مستقیم باقی‌مانده برای پاسخ به callback در پنل مدیر و dispatcher به helper امن منتقل شدند.
3. کار تهیه ZIP از حلقه اصلی ربات جداست؛ جمع‌آوری دیتابیس، لاگ Agentها و بسته‌بندی با مهلت‌های مشخص انجام می‌شود.
4. خطای دسترسی به دیتابیس یا Agent باید در خود ZIP به‌عنوان خطای جمع‌آوری ثبت شود، نه اینکه کل لاگ‌های محلی را از بین ببرد.
5. ارسال ZIP با مهلت‌های شبکه بلندتر و یک تلاش مجدد محدود برای خطاهای موقت انجام می‌شود.
6. تأیید SSH در صورت خطای شبکه می‌تواند از Agentهای مجاز استفاده کند؛ خطای احراز هویت یا تغییر اثرانگشت با failover دور زده نمی‌شود.
7. RelaySocket سازگاری بیشتری با API سوکت موردنیاز Paramiko دارد و قطع عادی WebSocket به‌عنوان پایان جریان مدیریت می‌شود.
8. نصب Agent قبل از انتخاب پورت، اشغال‌بودن آن و اختصاص پورت به endpointهای SSH دیگر را بررسی می‌کند؛ سرویس نامرتبط متوقف نمی‌شود.
9. نصب Agent برای حساب غیر root از `sudo -n` استفاده می‌کند و در نبود مجوز، خطای روشن `ADMIN_REQUIRED` برمی‌گرداند.
10. ساخت venv واقعی و اجرای pip بررسی می‌شود؛ نصب‌کننده می‌تواند بسته دقیق `python3-venv` را ترمیم کند و ابتدا از wheelhouse مرکزی با بررسی SHA-256 استفاده کند.
11. حذف پیام تکراری پیشرفت در زمان ارسال گزارش.
12. آزمون رگرسیون اضافه شد تا استفاده ناامن از پاسخ مستقیم callback در مسیرهای اصلی تشخیص داده شود.

## اعتبارسنجی محلی

- مجموعه آزمون: **۲۳۲ موفق، ۶ مورد skip، ۸ subtest موفق، صفر شکست**.
- بررسی نحو Python: موفق.
- بررسی Manifest SHA-256: موفق.
- بررسی سلامت ساختار ZIP: موفق.

شش آزمون به علت نبود وابستگی‌های `paramiko` و `python-telegram-bot` در محیط فعلی skip شدند. در این محیط، اتصال واقعی به سرورهای شما، SSH، TLS/WSS و PostgreSQL عملیاتی قابل آزمایش نبود؛ بنابراین این گزارش تضمین نمی‌کند که خطای محیط عملیاتی بدون اجرای staging برطرف شده باشد.

## نکات استقرار

- قبل از جایگزینی، از دیتابیس، تنظیمات، `secret.key` و `known_hosts` نسخه پشتیبان تهیه کنید.
- برای حساب `ubuntu`، دستور `sudo -n true` باید بدون درخواست رمز موفق باشد.
- پس از نصب، مسیر مستقیم و مسیر Agent جایگزین را روی یک سرور آزمایشی بررسی کنید.
- برای `HOST_KEY_CHANGED` اثرانگشت را مستقلاً از کنسول خود سرور بررسی کنید؛ اعتماد خودکار فعال نیست.
- اگر پورت Agent اشغال باشد، سرویس نامرتبط متوقف نمی‌شود؛ پورت جایگزین فقط پس از تأیید سلامت TLS/WSS در دیتابیس ثبت می‌شود.
