# رفع خطای HOST_KEY_UNKNOWN روی سرور ازقبل ثبت‌شده

**هدف:** تأیید امن کلید SSH سرور موجود، بدون حذف/ثبت دوباره سرور و بدون غیرفعال‌کردن بررسی اثرانگشت.

## علت

تأیید اثرانگشت SSH در مسیر افزودن سرور جدید وجود داشت، ولی مسیر «تست SSH» سرور موجود فقط خطای `HOST_KEY_UNKNOWN` برمی‌گرداند. کلید آن سرور در مخزن `KNOWN_HOSTS_FILE` تأیید نشده بود. این الزام امنیتی درست است؛ مشکل، نبود مسیر مدیریتی برای رفع آن بود.

## روش جدید در وب و مینی‌اپ

1. به **سرورها → جزئیات سرور → مدیریت عملیاتی** بروید.
2. **بررسی کلید SSH این سرور** را انتخاب کنید.
3. سامانه اتصال مستقیم از سرور مرکزی را آزمایش می‌کند و فقط در صورت خطای شبکه از Agent سالم و مجاز استفاده می‌کند؛ کلید دریافتی هنوز تأییدنشده است.
4. نوع کلید و اثرانگشت پیشنهادی `SHA256:...` نمایش داده می‌شود.
5. **خارج از اتصال SSH ربات**، با کنسول امن ارائه‌دهنده یا کنسول خود VPS اثرانگشت کلید عمومی مورد استفاده SSH را مشاهده کنید. برای Ed25519:

   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`

   اگر نوع کلید RSA یا ECDSA گزارش شد، کلید عمومی متناظر را بررسی کنید. مقدار خروجی باید دقیقاً با مقدار پیشنهادی تطبیق داشته باشد.
6. اثرانگشت تأییدشده را دستی وارد کنید؛ با کلیک «تأیید اثر انگشت و فعال‌سازی SSH سرور موجود»، سامانه **مجدداً کلید را اسکن می‌کند** و سپس با اطلاعات SSH ذخیره‌شده احراز هویت می‌کند. فقط در صورت موفقیت، کلید در known_hosts مشترک ربات ثبت می‌شود.
7. «تست SSH مرکزی / اجنت» را دوباره اجرا کنید.

## روش جدید در ربات تلگرام

از **جزئیات سرور → ابزارها و تست‌ها → بررسی و تأیید کلید SSH** وارد شوید؛ پس از مشاهده کلید و بررسی مستقل آن، مقدار SHA256 را ارسال کنید. اطلاعات سرور موجود دست‌نخورده می‌ماند.

## خطاها و اقدامات

- `HOST_KEY_UNKNOWN`: هنوز تأیید نشده؛ روند بالا را اجرا کنید.
- `HOST_FINGERPRINT_MISMATCH`: مقدار واردشده با کلید فعلی یکسان نیست؛ **هیچ کلیدی ثبت نشد**.
- `HOST_KEY_CHANGED`: کلید قابل‌اعتماد قبلی با کلید جدید متفاوت است. سامانه تغییر را **خودکار قبول نمی‌کند**. قبل از چرخش دستی کلید، علت تغییر/احتمال حمله را از کنسول سرور بررسی و نسخه پشتیبان بگیرید.
- `AUTH_FAILED`: نام کاربری، رمز یا روش ورود ثبت‌شده رد شده است؛ تأیید کلید نیازمند احراز هویت موفق است.
- `SSH_PORT_UNREACHABLE` / `SSH_TIMEOUT`: پورت، فایروال و مسیر Agent مجاز را بررسی کنید؛ این موارد مشکل اثرانگشت نیستند.

## استقرار و محدودیت‌های تأیید

- از دیتابیس، `secret.key` و **تمام محتوای `SONAR_STATE_DIR/.ssh/known_hosts`** بکاپ بگیرید. اطمینان حاصل کنید هر دو سرویس وب و ربات از یک `SONAR_STATE_DIR` پایدار و با مجوز نوشتن مشترک استفاده می‌کنند.
- به هیچ عنوان `AutoAddPolicy` را برای رفع این خطا فعال نکنید، known_hosts را کورکورانه پاک نکنید و رمز عبور SSH را در لاگ ثبت نکنید.
- آزمون‌های واحد بدون سرور واقعی اجرا شده‌اند. این بسته برقراری ارتباط واقعی با VPS یا Agent را اثبات نمی‌کند. به‌خصوص بازیابی پس از مهاجرت سیستم و چرخش واقعی کلید باید جداگانه آزموده شود.
