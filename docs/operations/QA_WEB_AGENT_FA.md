# گزارش نهایی QA — Sonar Radar Pro 6.6.0 RC3

تاریخ بازبینی: ۲۲ اکتبر ۲۰۲۶

## نتیجه آزمون‌های محلی

- Pytest: **۲۳۲ موفق، ۶ skip شده، ۸ subtest موفق**.
- `python -m compileall -q .`: موفق.
- `bash -n` برای تمام فایل‌های Shell: موفق.
- `node --check` برای ۶ فایل JavaScript: موفق.
- بررسی Manifest: ۱۸۱ فایل منبع تأیید شد.

## خطاهای پوشش‌داده‌شده

- Callback قدیمی تلگرام و جلوگیری از توقف عملیات به‌علت خطای پاسخ Callback.
- تهیه ZIP هفت‌روزه به‌صورت پس‌زمینه و تحمل timeout یک Agent یا یک مرحله جمع‌آوری.
- حذف متن خام exception از اعلان مدیر.
- انتقال عملیات دیتابیس داشبورد Agent و وضعیت سرور از Event Loop.
- تأیید مستقل اثرانگشت SSH و failover فقط برای خطای شبکه.
- بررسی تعارض پورت Agent و حفظ سرویس‌های نامرتبط.
- تلاش مجدد برای ساخت venv با بسته Python متناسب و اجرای عملیات مدیریتی با `sudo -n`.

## آزمون‌های skip شده

شش آزمون به‌دلیل نبود `paramiko` و `python-telegram-bot` در محیط ساخت اجرا نشدند. آزمون زنده SSH، TLS/WSS، Telegram و PostgreSQL نیز در این محیط در دسترس نیست.

## چک‌لیست استقرار آزمایشی

1. از دیتابیس، `secret.key` و `known_hosts` نسخه پشتیبان بگیرید.
2. از حساب عملیاتی، `sudo -n true` و `sudo -n id -u` را بررسی کنید؛ دستور دوم باید `0` برگرداند.
3. اثرانگشت SSH را از کنسول سرور مستقل بررسی و سپس در پنل تأیید کنید.
4. نصب Agent را با پورت آزاد و پورت اشغال‌شده آزمایش کنید؛ سرویس نامرتبط نباید متوقف شود.
5. ارتباط مرکزی را آزمایش کنید؛ سپس فقط برای آزمون، مسیر مستقیم را قطع کنید و Agentهای تأییدشده را به ترتیب بررسی کنید.
6. ZIP هفت‌روزه را از تلگرام و پنل دریافت و وجود گزارش‌های bot، web، install و Agent را بررسی کنید.
7. پس از راه‌اندازی، لاگ‌های جدید را برای `EVENT LOOP LAG`، `SSH_CONNECTION_FAILED`، `AGENT_PORT_CONFLICT` و `VENV_CREATE_FAILED` کنترل کنید.

**نتیجه:** همه آزمون‌های اجراشده موفق‌اند؛ این نتیجه به‌معنای تأیید اتصال زنده به زیرساخت تولیدی یا تضمین نبود خطا در تمام شرایط شبکه نیست.
