# اصلاحات وب/Agent پس از 6.6.0 RC3 — گزارش قابل ممیزی

**وضعیت:** اصلاحات کد + آزمون‌های آفلاین؛ هنوز *تأیید شده در VPS واقعی* نیست.

## مشکلات مشاهده‌شده در لاگ‌های ۲۱ اکتبر ۲۰۲۶

- ثبت `SSH relay unavailable; agent_id=4; error_type=AttributeError` مکرراً.
- خطای `ConnectionClosedOK: sent 1000 (OK)` در Paramiko هنگام بسته‌شدن کانال SSH روی WS.
- برای برخی سرورها `Agent is not TLS-enrolled` گزارش شده است.
- `web.log` فقط خطای دسترسی به journald را نشان می‌دهد؛ از این لاگ نمی‌توان شکست API وب را استنتاج کرد.
- فایل `install.log` خالی است؛ وضعیت نصب Agentها از داده‌های تشخیصی کامل نیست.

## تغییرات اعمال‌شده

- `web_operations.py`: ویزارد دو مرحله‌ای probe/confirm، SSH با اثرانگشت مستقل، نصب اختیاری، تست دوباره SSH، پورت Agent، rename/group، مدیریت پوشه و حذف تأییدی.
- `server_onboarding.py`: اولویت اتصال مرکزی، fallback فقط بر خطای شبکه و تنها با Agent سالم/تأییدشده، بدون دورزدن host key/auth.
- `web_agent_jobs.py`: صف مبتنی بر PostgreSQL با محدودیت هر سرور، ثبت مرحله، دامنه مالکیت و نمایش وضعیت؛ نصب با موتور خود ربات انجام می‌شود.
- `ssh_support.py`: بسته‌شدن صحیح Paramiko قبل از WebSocket و کاهش خطای بستن سوکت زیر Transport فعال.
- `ssh_relay.py`: مدیریت بسته‌شدن عادی WebSocket در رابط شبه‌سوکت.
- `database.py`: جابه‌جایی حذف group و جداکردن سرورها برای رعایت وابستگی کلید خارجی.
- `pro_web/`: افزودن وضعیت و عملیات جدید به هر دو نوع احراز هویت Web و Telegram Mini App.
- یکپارچگی منبع: اضافه کردن `.gitignore`، قالب env، CI، فایل‌های نقشه و حذف کپی‌های دقیق آرشیوی.

## محدوده تأیید و کارهای باقیمانده

- تست‌های واحد و بررسی کامپایل/JS/Shell آفلاین اجرا می‌شوند. جزئیات نتایج در `QA_WEB_AGENT_FA.md` است.
- دسترسی به VPS واقعی، PostgreSQL دارای داده، ربات تلگرام، WSS پین‌شده و شرایط اختلال شبکه برای تست انتهابه‌انتها در این محیط وجود ندارد.
- همه قابلیت‌های تلگرام (از جمله فرمان‌های مدیریتی پرخطر، پرداخت، ترمینال SSH تعاملی و همه ویزاردهای قدیمی) هنوز به نسخه وب منتقل نشده‌اند؛ انتقال کامل نیازمند توسعه و تست مجزاست.
- علت دقیق `AttributeError` با لاگ‌های فعلی اثبات نشده؛ بسته‌شدن زودهنگام سوکت اصلاح شد، ولی تأیید قطعی رفع خطا به لاگ و تست محیط واقعی وابسته است.
- صف فعلی از دیتابیس استفاده می‌کند اما برای نصب‌های بسیار طولانی، مقیاس چندپردازه‌ای و خاموشی سرویس باید تست عملیاتی/بازیابی انجام شود.
- تغییر پورت SSH در رله فقط برای پورت‌های مجاز در تنظیمات مرکزی و Agent امکان‌پذیر است.

پیشنهاد استقرار: ابتدا از دیتابیس، فایل رمزنگاری و trust store نسخه پشتیبان تهیه کنید؛ روی یک VPS آزمایشی مسیر مرکز، قطع مرکز، Agent، fingerprint اشتباه، رمز اشتباه، شروع مجدد وب وسط نصب و نگهداشت داده‌ها را تست کنید.
