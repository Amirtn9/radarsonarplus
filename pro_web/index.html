مدیریت عملیاتی سرور

کلید نمایش‌داده‌شده فقط از شبکه خوانده شده و قابل اعتماد نیست. اثر انگشت واقعی را جداگانه در کنسول سرور بررسی کنید. ثبت فقط پس از احراز هویت SSH انجام می‌شود.

تعمیر Agent، سرویس و گواهی TLS را از مسیر SSH معتبر بررسی می‌کند؛ پس از تست واقعی WSS، گواهی در دیتابیس دوباره ثبت می‌شود.

🌐 بررسی دسترسی از داخل و خارج

این آزمایش فقط اتصال TCP از مسیرهای موجود را بررسی می‌کند و تشخیص قطع کامل اینترنت نیست.

مرکز عملیات سازمانی

وضعیت نامشخص برای داده کهنه؛ امتیاز سلامت فقط از داده تازه محاسبه می‌شود.

اجرای عملیات گروهی

عملیات در PostgreSQL ثبت می‌شود و Worker مستقل با SSH/Agent، مجوز و شناسه یکتا آن را اجرا می‌کند. Restart فقط برای سرویس‌های مجاز است.

تحلیل سازمانی ۳۰ روزه

زمان‌بندی پشتیبان‌گیری

کلید رمزنگاری SONAR_BACKUP_ENCRYPTION_KEY باید روی سرور تنظیم شده باشد؛ مقصد محلی در SONAR_BACKUP_DIR محدود است؛ برای S3 از s3://bucket/prefix و متغیر SONAR_BACKUP_S3_BUCKET استفاده کنید.

انتشار تدریجی Agent

برای انتشار باید فایل Agent و امضای Ed25519 آن را بارگذاری کنید.

Artifact پیش از ذخیره و هر بار پیش از نصب با Ed25519 و SHA-256 تأیید می‌شود. کلید عمومی باید روی Backend تنظیم شده باشد. Rollback گروهی فقط وقتی ممکن است که نسخه قبلی نیز به‌عنوان Release امضاشده ثبت شده باشد.

Webhook

Secret فقط یک بار نمایش داده می‌شود. مقصدهای خصوصی و IPهای غیرعمومی رد می‌شوند.

سیاست Health Score

مجموع وزن‌ها باید دقیقاً ۱۰۰ باشد. داده کهنه همچنان Unknown باقی می‌ماند.

🔔 اعلان و زمان‌بندی کانفیگ‌ها

اعلان قطعی و بازیابی پس از سنجش واقعی؛ تست زمان‌بندی‌شده به Agent سالم نیاز دارد. مقصد پیام‌ها در بخش کانال‌ها تعیین می‌شود.

خالی‌بودن هر دو ساعت یعنی سکوت غیرفعال است. برای سکوت شبانه مثلاً ۲۲ تا ۷ را وارد کنید. هشدارها در ساعت سکوت نگهداری و بعد ارسال می‌شوند. خاموش‌کردن همه اعلان‌ها، تست و گزارش خودکار همین بخش را هم متوقف می‌کند.

🛰 استخر Agentهای چندمنطقه‌ای

این بخش پیشنهادهای Agent در ایران و خارج را مدیریت می‌کند. وضعیت WSS، گواهی TLS و توکن جداگانه بررسی می‌شوند؛ باز بودن پورت به‌تنهایی سلامت Agent را ثابت نمی‌کند.

در حال بارگذاری Agentها…

🧩 نصب چندتایی Agent

برای سرورهای فعال متعلق به مدیر اصلی در ایران یا خارج؛ نصب فقط پس از تأیید SSH انجام می‌شود. مالکان دیگر باید Agent را روی سرور خود نصب و برای اشتراک پیشنهاد کنند.

آخرین عملیات نصب

📊 مصرف ارتباطی Agentها (فقط مدیر)

آمار واقعی بایت‌های WSS و تونل SSH، بدون ادعای اندازه‌گیری دانلودهای مستقل Xray یا کل ترافیک VPS. ثبت اطلاعات نمونه‌برداری است.

🔌 آزمایش اتصال چند پورت

پورت‌های رایج و پورت ثبت‌شده همان سرور بررسی می‌شوند؛ این کار پورت یا Agent را تغییر نمی‌دهد.

بالانسر ارتباطات چندمسیره

ترتیب قطعی: سرور مرکزی ← Agent اولویت‌دار ← Agent پشتیبان بعدی. مسیر فقط پس از خطای شبکه عوض می‌شود؛ خطای اثرانگشت یا احراز هویت هرگز با مسیر جایگزین نادیده گرفته نمی‌شود.

مدیریت Agentهای ایران و خارج

برای فعال شدن در بالانسر، Agent باید نصب شده، دارای گواهی TLS و توکن معتبر، تأییدشده توسط مدیر و دارای heartbeat موفق در پنج دقیقه اخیر باشد.

در حال دریافت سرورها…

🩺 مرکز عیب‌یابی مدیر

خروجی شامل لاگ‌های ربات و پنل، فایل‌های چرخشی، وضعیت عملیاتی دیتابیس و لاگ Agentهای ذخیره‌شده در بازه انتخابی است. خطوط و stack traceها حذف نمی‌شوند؛ مقادیر محرمانه در همان خط پوشانده می‌شوند. فایل‌های اصلی روی سرور دست‌نخورده باقی می‌مانند.

برای بررسی سلامت دکمه بالا را بزنید.

مدیریت لاگ‌های پایگاه داده

رویدادهای برنامه و تاریخچه فعالیت تمام کاربران؛ فقط مدیر اصلی دسترسی دارد. نگهداری لاگ برنامه ۳۰ روز و فعالیت‌ها ۹۰ روز است. فایل‌های چرخشی، journal سیستم و لاگ روی Nodeها جداگانه در خروجی عیب‌یابی باقی می‌مانند و با این دکمه حذف نمی‌شوند.
